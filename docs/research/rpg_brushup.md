# RPG・協力アクションの先行例と、この Mod の磨き直し案

調べ物の記録（設計書ではない）。ベータの試遊の声（装備なしで心臓へ突っ込む／倒れた直後に戦いへ戻される／パーティで共有した碑／予告が読めない／ボス部屋が狭い／墓の置き場／巨神が 20 分居座る／乗り込みの待ち／呼び笛の混乱／持ち物の散らかり／巨神前の量／初回と周回）に対し、先行作品の扱いと今の設計（21・22・02・09・10・11・20）を突き合わせ、直す順番をつけた。

- 区分: **(A)** ユーザーの判断なしで進めてよい（既存の決まりを変えない、見え方・誘導・検査の追加）。**(B)** 決まりや見た目の方向が変わるのでユーザーの判断が要る（選択肢 2〜3 と推奨つき）。
- 影響・工数は 大/中/小。参照の URL は短く付けた。引用は数語まで。
- **出典の質について**: 検索で出た資料の多くはファンの wiki・掲示板・攻略記事で、公式の設計意図ではない。そのため「作品がこうしている」と書いたのは、URL で確かめられた事実か、広く知られた仕様（※印）に限った。設計意図の推測は「示唆」と書いた。数値（上限回数など）を設計に使う前は、各作品の公式資料で確かめること。

## 1. 装備なしの突撃と「備えの確認」

**先行例**
- Monster Hunter: クエストごとに力尽きていい回数が決まっている（既定 3。同じ回数の中で全員が共有する、と書く攻略もある）。強さの目安は上位・下位のランクと依頼板で段階づけ、物語の節目は **ランクの関門**で止める。https://deltiasgaming.com/?p=160190 ／ https://deltiasgaming.com/?p=143651 　※一つの攻略記事は「力尽きるたびに報酬が減る」とも書く（要・公式確認）。
- Terraria / Valheim: **装備と素材が関門**。Terraria はスケルトロンを倒すまでダンジョンが 9999 ダメージの守りで固められている（攻略記事より）。Valheim は、地域の素材で装備を作り、祭壇でボスを自分で呼び、その報酬が次の地域の鍵になる。https://www.thegamer.com/terraria-boss-progression-guide/ ／ https://allthings.how/valheim-progression-guide-every-biome-boss-and-key-drop/
- Elden Ring: 関門は「ボスが強い」だけ。装備の強さは選べる。ボスは休息の恵みで復活しない（wiki）。https://eldenring.wiki.gg/wiki/Boss

**今の設計**
- 良い: 備えの三灯（身・刃・糧）が控え帳・乗り込み口・イサナの一言で見える。ふさがない（21 の 0.2）。旅装・砥石で緑まで届く。復活は人ごと 3 回・20 秒待ち・3 秒光る（21 の 1.3）。これは MH の「3 回」と Souls の「走って戻る」の中間で、穴は塞がれている。
- 穴: 備えは「見ようとした人」にしか見えない。パーティの誰かが赤でも、他の人は気づかないまま扉が閉まる。赤のときの「次に何をすればよいか」が一行で出るかは未確認（11 の 9.2 を読み直す必要がある）。

**提案**
- **A2（準備確認）**: 【実装済み: 設計書 11 の 9.2 の 4・18 の 8.1 に現行仕様。`SELFTEST readiness`。ほかの人へは「仲間の誰かの備えが低い」だけ。赤の本人の一行は字幕、扉までの秒はアクションバーの同じ一行】 扉が閉まる 5 秒の予告（02 の 4.2）の間に、参加しそうな人へ「備え: 身 緑・刃 赤・糧 黄」を一行（アクションバー）で出し、**赤の本人にだけ**「刃が低い。砥石を」を足す。ほかの人には「仲間の誰かの備えが低い」だけ（名指ししない）。ふさがない。触る所: `readiness/`、`TitanBackTrials` の予告、`Notice`（18）。FFXIV の準備確認（ready check）※ と同じ型だが、押させない。
- **A7（手段つきの一行）**: 【実装済み: 設計書 11 の 9.2。`ReadinessAdvice`・`Readiness.registerRemedy`。控え帳の詳細と乗り込みの一言に出る。砥石・旅装の登録はまだなので、手段は今ある物だけ（作る・拾う・共鳴の炉・食べ物・水薬・装飾品。鼓動守は登録済み）。旅装・砥石・職人は、登録口に入った時点で自動で名前が出る】 赤のとき「何が足りないか」だけでなく「どこで直せるか」（旅の覚書・職人・砥石）まで出す。
- **B6（倒れた回数と報酬）**: 【決定・実装済み: (2)。設計書 10 の 10.14・11 の 3.1。`FightBadges`。0 回「無傷の誓い」・2 回まで「堅き歩み」。報酬は変えない】 選択肢 (1) 今のまま（報酬は変えない）／(2) 倒れが少ない・復活が 0 のときだけ**見た目の称号や札**を足す（罰ではなく褒美）／(3) MH のように倒れるごとに報酬を減らす。**推奨 (2)**。罰を足すと「ソフトな死の罰」（ベータ 2）に反する。(2) は周回の動機にもなる。
- **B7（扉の前の確認）**: 選択肢 (1) 今のまま／(2) 赤の人が扉に触れたとき「本当に挑みますか」の一言を挟む／(3) 赤の人は参加できないようにする。**推奨 (2)**。(3) は「ふさがない」に反する。

## 2. 倒れたあとと再入場（「復活したらすぐ戦いだった」）

**先行例**
- MH: 力尽きる → 拠点へ戻って回復用の品を整え、**自分の足で戻る**。戻るまでに数十秒かかる。回数の上限で失敗。
- Elden Ring: 戻りは恵みから走る。「走る時間が長すぎる」という不満と「30 秒ほど」という反論が両方ある（掲示板）。https://steamcommunity.com/app/1245620/discussions/0/3801650156483407969 　示唆: **待ちは 20〜30 秒が許容の端**。長いと不満が出る。
- Deep Rock Galactic: 協力では**仲間が起こす**。複数人なら際限なく起こせて、全員が倒れたときだけ失敗、と言われる（掲示板）。ひとりのときは相棒が限られた回数だけ起こす。https://steamcommunity.com/app/548430/discussions/1/3951406749566658038 　示唆: 協力では「倒れた人を仲間が戻す」行為が楽しみの核になる。
- FFXIV: 全滅（wipe）すると入口へ戻り、同じ部屋で何度でもやり直せる※。復活の魔法で仲間を起こす役割がある※。

**今の設計**
- 良い: 戦いの最中の復活先は心臓の間で、扉の外から離れた隅（02 の 7.3）。20 秒の待ちと残りの表示。3 秒の無敵。復活は戦いの部屋の中に入らない。観戦できる。
- 穴: (a) 3 秒の無敵は「扉から戻るとき」だけ。戦いの外の背中（廊下・休み場の外）で復活した直後の保護は書かれていない。(b) 上限を使い切った人は観戦のみで、仲間が起こす手段がない（DRG との差）。

**提案**
- **A3**: 【実装済み: 設計書 02 の 7.3・10 の 10.9・11 の 3.1 と 6.5.1・18 の 8.1 に現行仕様。`SELFTEST ux polish`】 背中の復活（どこでも）にも、短い光（2〜3 秒）と「その間は敵に狙われない」を付ける。復活地点の半径 6 ブロックは敵が湧かない・入らない（休み場の焚き火のまわり）。触る所: `TitanBackTrials` の復活処理、`Reentry`、`GuardMob` の探索。
- **B1（復活の上限の運用）**: 【決定・実装済み: ユーザーが「仲間が起こせる仕組み」を選んだ。設計書 02 の 4.2・10 の 10.12 に現行仕様。`SELFTEST party revive`。倒れた状態 15 秒・3 秒の長押しで起こす・体力 3 割・再入場の回数に数えない。上の案 (2) より大きく、回数を戻すのではなく「死なせない」形】 (1) 今のまま（人ごと 3 回）／(2) 仲間が倒れた人のそばで一定時間しゃがんで「起こす」と、その人の上限を 1 回戻す（DRG の型。起こす側は戦いに戻る）／(3) パーティで共有の回数（MH の型。人数 × 2 回など）。**推奨 (1) を保ち、(2) は小さな機能として後で足す**。(3) は「あの人のせいで使い切った」の火種になる（掲示板の cart 論争の型。https://hostedgg.com/blog/monster-hunter-carting-culture）。

## 3. 予告の読みやすさと色（色覚対応を含む）

**先行例**
- FFXIV: 地面の予告は**橙が標準**。形は円・輪・線・扇・四角。ほかに黄の山形（追尾）、色つきの矢印（散開）。赤は少数の特別な場面で、当たりが遅れて来るものもある（wiki）。高難度では予告が当たる直前にしか出ないので、詠唱名と動きも読む。https://ffxiv.consolegameswiki.com/wiki/Area_of_Effect 　示唆: **色の意味を一つに保つ**ほど覚えやすい。
- 色に頼らない原則: Xbox の指針は「重要な手がかりは色だけにせず、形・模様・アイコン・文字も使う」。https://devdocs.xbox.com/gaming/accessibility/xbox-accessibility-guidelines/103 　Diablo IV は強調の色を選べる。Lost Ark は色覚用のフィルターがある。https://caniplaythat.com/2023/05/23/diablo-iv-accessibility-detailed-by-blizzard/ ／ https://help.playlostark.com/hc/en-us/articles/37754234136475
- Minecraft の Mod: 技の溜めの**動き**を手がかりにする（Mowzie's Mobs の Wroughtnaut は叩きつけの溜めが合図。更新履歴に「跳んで避けられる」）。Blom のように「全部の技に床の印」と謳う Mod もある。https://www.curseforge.com/minecraft/mc-mods/mowzies-mobs/files/3619919 ／ https://moddex.gg/mod/blombosses
- Elden Ring への不満: 予告が短く覚えないと避けられない、狭い場所で大技が見えない（掲示板）。https://steamcommunity.com/app/1245620/discussions/0/3729575504108842499/?l=danish

**今の設計（02 の 5.3・5.4）**
- 良い: 印と当たりが同じ形。予告 0.8 秒以上（心臓は 1.2〜2 秒）。進みで満ちる縁・近づくと白くなる。跳べば避けられる技を明記。粒は「制限を無視」でパーティクル最小でも見える。技ごとの専用音。
- 穴 1（色）: 心臓の技の色が 淡い青・橙・赤・緑（安全な筋）・暗い赤・灰色・水色 と技ごとに違う。**青で傷が出る**（突きの帯・叩きつけの円）のは、多くの作品で青を味方・安全に使う慣れと逆。赤い円と**緑の安全な筋が同居**するのは、赤緑の色覚の人にはほぼ同じ色（一般的な色覚の知識）。
- 穴 2（描き方）: 粒の輪郭と縁だけで、面が塗られない。FFXIV は面を塗る。広い扇や円の中が「どこまで当たるか」が粒の密度に頼る。粒の予算（1 tick 700）のため、大きい円は粗くなる。
- 穴 3（人数）: 6 人のとき技の数が増える（別の人へ向けた帯が 3〜5 本）。本数が多いと、**自分への帯がどれか**が分からない。

**提案**
- **A1（配色の統一）**: 「当たる範囲 = 橙〜赤（時間とともに橙 → 赤 → 白）」「安全な筋・輪を抜ける場所 = 水色または白の輪郭」「ノックバックだけで傷なし = 灰」の三つに絞る。今の青い突きの帯と青い叩きつけの円は橙へ。緑の筋は水色の輪郭へ。技ごとの色の違いは**形と音**で出す。触る所: `combat/Telegraph`（既定色）、各 `.color(...)`（番兵長・四体の心臓）、02 の 5.3 の表、`TelegraphSelfTest`（色の取り決めの検査）。
- **A1 の続き（形で見分ける）**: 安全な筋は**破線の輪郭 + 塗りなし**、当たる面は**縁に内向きの山形（FFXIV の山形に相当）を並べる**。色を失っても形で読める。
- **A1 の続き（自分への帯）**: 自分を狙う帯だけ、始点の足もとに小さな輪を出す（他の人を狙う帯には出さない）。人数が増えても「自分のはどれか」が分かる。
- **B2（描き方）**: (1) 今のまま粒だけ／(2) クライアントが形を受け取って**床に半透明の面を描く**（サーバーの当たりは今のまま。粒は補助）／(3) 表示用エンティティ（Display）で面を描く。**推奨 (2)**。粒の予算に縛られず、塗りで見える。工数は大（描画の部品とパケットが一つずつ）。先に 1 技で試作して見比べるとよい。
- **B3（色覚の選択）**: (1) 全員に色覚で安全な固定の配色／(2) 設定で 3 配色（標準・赤緑向け・高コントラスト）から選べる。**推奨 (1) を A1 で実現し、(2) は B2 のあとで**。固定で安全にしておけば設定の説明が要らない。
- 音と動き: 予告の始まりの音は「当たる技」と「避けるだけの技」で別にする（耳でも分かる）。ボスの溜めの動きは予告の開始と合わせる（Mowzie's の型）。これは 15 の骨アニメの担当で、設計は決まっているので A。

## 4. ボス部屋の広さ

**先行例**
- Elden Ring: 狭い部屋で大技が見えず、壁で視点が詰まる不満（掲示板）。上の Steam の議論。
- FFXIV: 戦いは円形の広い床で、外周の安全な縁と中央の動きが設計されている（一般的な知識※）。

**今の設計**
- 良い: 岩鯨の心臓の間は半径 19・高さ 12 に広げ済み（02 の 3.4。「前は輪や扇に対して狭かった」と記録）。最大の予告（骨の投射の長さ 30、輪の半径 16、光線の射程 24）に対し、床の半径 19 は足りる範囲。
- 穴: 潮殻・雷翼・余燼の広間の広さが同じ基準で検査されているか不明。人数 6 人の安全な楔（光線の扇のあいだ）の幅も、広さに依存する。

**提案**
- **A5**: 基準を一行で決める。例: 「使える床の半径 ≥ 最大の予告の到達 × 0.8（長さ 30 の帯は中心から 24）」「天井 ≥ 12」「視点を遮る柱は中心から半径 3 以内に置かない」。`TelegraphSelfTest` に「各心臓の全技を、部屋の中の最も端から撃っても、安全な床が残る」検査を足す（今の「安全な床が残る」検査の延長）。触る所: `TelegraphSelfTest`、各背の `*Layout`、02 の 3.4・08/12/13 の同じ節。

## 5. 墓の置き場所と取り戻し

**先行例**
- Minecraft（バニラ）: 回収コンパス（Recovery Compass）が最後の死に場所を指す。※
- Souls 系: 倒れた場所に魂が残り、**一度戻るまでは再度の死で消える**（取り戻しを促す緊張）。この Mod は消えない墓で緊張を意図して捨てた（ベータ 2 の「全ロスは萎える」）。

**今の設計（11 の 6 章）**: 墓は消えない・複数・ブロックを壊さない・置けなければ預かり。語り部の救い（50%）。控え帳に座標。
- 穴: 置き場の探索は丁寧だが、**取りに行く道しるべ**が控え帳の座標だけ（画面を開かないと分からない）。仲間が近くにいるとき、墓の場所を共有する手段もない。

**提案**
- **A8**: 【実装済み: 設計書 02 の 7.3・10 の 10.9・11 の 3.1 と 6.5.1・18 の 8.1 に現行仕様。`SELFTEST ux polish`】 復活時に「墓の標」を HUD に出す（`PartyMarkers` と同じ投影。矢印・距離・墓の絵）。墓へ 8 ブロック以内で消える。墓がある間、控え帳を開かなくても見える。触る所: `record/` の墓、`party/client/PartyMarkers` の流用、`Notice`（18）。パーティの仲間には**他人の墓の標は出さない**（開けられないため。10 の 6.5）。
- 置き場の補足（既に良い案）: 溶岩・水・虚空のときの近い安全な場所（11 の置き場 1〜5）は先行例より丁寧なので、変えない。

## 6. 巨神の滞在・乗り込みの待ち・呼び笛

**先行例**
- Zelda（BotW/TotK）: 祠はそのまま**旅の起点**になる（クリアで移動先が増える。https://www.zeldadungeon.net/wiki/Tears_of_the_Kingdom_Key_Items など）。道具は「ボタンで出す」。
- Pokémon: **登録した大事な道具をワンボタンで使う**（べんりボタン。世代により 1〜複数登録。https://bulbapedia.bulbagarden.net/wiki/Feature_registration ）。
- FFXIV（※）: 出発前は準備確認、全員が押すと即開始、待ちが長いと自動で打ち切る。

**今の設計（09）**
- 乗り込みの待ち: 出発の待ち 60 秒（延長で最大 90 秒）。二度目に笛を吹くと、全員乗っていればすぐ出発。巨神は降ろしたあと 20 分居座る。クールダウンは呼んだ人 3 分。
- 良い: 理不尽がない作り（09 の 8 章）。海図・残り秒数・ボスバー。
- 穴: (a) 60 秒は待ちが長い。しかも「全員が乗ったら出る」が**二度目の笛**という隠れた操作で、知らないと 60 秒待つ。(b) 「笛を吹く」「海図で出発」「二度吹く」が別の意味で混ざっている（呼び笛の混乱の原因と読める）。(c) 20 分居座りは、他の人が使えるが、巨神がその場に残ると見た目が邪魔・サーバーの負荷になりうる。

**提案**
- **A6**: 【実装済み: 設計書 09 の 4.2.1。`TravelRules.autoDepartLimit`。`SELFTEST travel`。二度目の笛での早い出発は廃止（海図に「出発」の項は無い）。段階の表示は出発の待ちの帯（ボスバー）を残し、全員乗ったら緑の「全員乗った。N 秒で出発」。笛の説明は一行（吹く → 乗る → 行き先を決める）にした。常時の隅の段階表示は未着手】 近くの（64 ブロック以内の）同じパーティの人が全員乗ったら、**5 秒の合図で自動出発**。段階の表示（呼んでいる／鎖が降りる／あと N 秒／泳いでいる）を呼び笛の持ち手の画面の隅に常時出す。笛の道具の説明を一行にする（「吹く → 乗る → 行き先を決める」）。触る所: `titan/travel`（`Voyage`・BOARDING）、`TravelClient`、lang。二度目の笛は残す（互換）。
- **B5（居座り 20 分）**: (1) 今のまま／(2) 5 分に短縮し、その間に誰かが背中へ乗れば延長／(3) 近くに人がいなくなって 3 分で去る。**推奨 (3)**。人がいるあいだは使えて、無人で居座らない。
- **B8（出発の操作）**: (1) 今のまま／(2) 二度目の笛をやめ、海図に「準備完了」を全員が押せる（全員で押すと即出発）／(3) A6 の自動出発のみ。**推奨 (3) のあと様子を見て (2)**。

## 8. 巨神前の量・初回と周回

**先行例**

**提案**
- **A9**: 【実装済み: 設計書 11 の 9.4。`record/ChapterChecklist`。備えの頼み・寄り道（見つけた数 / 全数・終えた数）・旅の覚書。次の目的は出していない】 控え帳の巨神の頁に「この章の進み」（備えの頼み 3 本の済み/残り、寄り道の見つけた数 / 全数（輪郭だけ）、次の目的）を出す。物語の核心は出さない（17 の 5 章）。触る所: `record/`、`quest/`、lang。
- **B4（周回の変化）**: (1) 今のまま／(2) 周回のたびに休み場の碑の囁きと語り部の一言を変える（文だけ。ホラーを足さない）／(3) 周回でだけ出る小さな条件（その周の「祝福」のような一つの縛りと報酬）。**推奨 (2)**。(3) は新しい仕組みで、03 の曲線と衝突しうる。

## 10. マルチプレイの見え方（共有の進み・目印・色）

**先行例**
- Souls / Elden Ring: 呼ばれた協力者は、ボスの人数で**ボスの体力が増える**（人数で決まりレベルでは決まらない。攻略記事）。進みの旗はホストのもので、協力者には付かない（※）。https://expertbeacon.com/how-does-summoning-work-in-elden-ring-level-difference/ 　示唆: 助けた人が「自分の世界では未クリア」になる摩擦は、先行例でも定番の不満。
- MH: 力尽きる回数の共有（上記）。
- FFXIV: 戦利品は人ごとの週上限。パーティの目印（マーカー）を地図に置ける（※）。

**今の設計（10）**
- 良い: グループごとの進み・扉・敵・予告の見え方（他グループには見えない）。仲間の位置の HUD（距離・体力の札）。経験値の分け前（居合わせた人 100%、そうでない仲間 70%）と放置の仲間へは渡さない。ボスの体力倍率 1 + 0.6 ×（人数 − 1）は Souls と同じ「人数で決まる」型。
- 穴: (a) 碑（共鳴石など）は鳴らした人が一人でも**全員が踏破**になる（10 の 10.9）。試遊の「パーティ共有の碑」の声は、**誰が鳴らしたのか・自分は踏破したのか**が見えないこと、**先を越されて見損なう**ことと読める。(b) 仲間への目印の手段が位置の自動表示だけで、「ここ」と指す手段がない。(c) 仲間の矢印・札の色が色覚に配慮されているかが書かれていない。

**提案**
- **A4**: 【実装済み: 設計書 02 の 7.3・10 の 10.9・11 の 3.1 と 6.5.1・18 の 8.1 に現行仕様。`SELFTEST ux polish`】 碑の状態を三つに分けて見せる: 「あなたが鳴らした」「〇〇が鳴らした（あなたは踏破として数える）」「まだ」。碑の灯りの色を、自分が鳴らした碑だけ違う（形でも違う: 輪の模様）にする。控え帳の巨神の頁にも「自分が鳴らした数 / 仲間が鳴らした数」。仕組み（共有）は変えない。触る所: `titan/group/TrialSteles`、各背の石、`Notice`、`record/`。
- **B4b（碑の共有そのもの）**: (1) 今のまま（パーティで共有）／(2) 扉の通りはグループ共有のまま、**経験値・欠片などの人ごとの記録は本人が鳴らしたときだけ**付く（仲間が鳴らした碑は触れば「見た」に変えられる）／(3) 全員が各自触る。**推奨 (2)**。進みを止めず、体験を飛ばした感じも減らす。
- **A11（仲間の札の色）**: 【実装済み: 設計書 02 の 7.3・10 の 10.9・11 の 3.1 と 6.5.1・18 の 8.1 に現行仕様。`SELFTEST ux polish`】 仲間の矢印・札は色のほかに**記号（番号・形）**を付ける（体力は色でなく棒の長さ）。`PartyMarkers`。
- **B10（簡易の目印）**: 【決定・実装済み: (2)。設計書 10 の 10.13・18 の 8.2。`party/Ping`。キー X・8 秒・敵の印あり。柱ではなく HUD の印（色に頼らない形）】 (1) 足さない／(2) 「ここ」ボタン（キー 1 つ。パーティに 10 秒だけ光る柱）／(3) 地図への印。**推奨 (2)**。FFXIV の目印や Apex 型の ping の簡易版（※）。小さな機能で、パーティの「どこ？」を減らす。ただし新規のキーとパケットが要るので B。
