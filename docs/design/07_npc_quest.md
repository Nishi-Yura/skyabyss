## 2. 物語の流れ

### 2.1 メイン「雲の下の歌」（`main_song`）

序章の帳面から、岩鯨の心臓を止めて天の鍵の欠片を手に取ろうまでを、一本の道にする。

| 段 | プレイヤーが知ること | やること | 済ませ方（フック先） |
| --- | --- | --- | --- |
| 始まり | 野営地に帳面が残されていた。遠くに煙が立つ | — | 帳面を拾う（伝承 `prologue/the_book`）と自動で始まる。空の影を先に見る（`prologue/shadow`）か、先に岩鯨を見つける（`chapter1/stone_whale`）でも始まる。語り部に「空のことを」と尋ねても始まる |
| 序 1 `follow_smoke` | 煙の下の「鐘の宿り」に語り部がいる | 煙の下の鐘の宿りへ向かおう | 語り部の節 `shadow0` に入る。影や岩鯨を先に見た人、空のことを先に尋ねた人（印 `sky_asked`）は飛ばす（`skip_if`） |
| 序 2 `watch_sky` | 今日あたり、空を見ていなさい | 晴れた昼に、空を見上げてみよう | 伝承 `prologue/shadow`。見たら次へ |
| 1 `ask_storyteller` | 影の年には遠い空から“歌”が聞こえる。歌を追う旅人がいる | 語り部に尋ねる | 語り部の節 `shadow3` に入る |
| 2 `find_chaser` | 歌の主は空を泳ぐ岩の鯨。降りてきて鎖を垂らす | 外れの鯨追いに話を聞く | イサナの節 `c_whale2` に入る（イサナは、この段のときに村の外れへ火を焚いて現れる） |
| 3 `see_whale` | 歌が聞こえたら空を見ろ | 岩鯨をその目で見る | 伝承 `chapter1/stone_whale`（160 ブロック以内に岩鯨） |
| 4 `board` | 鎖をつかめば背中へ | 鎖をのぼり背中へ渡る | 伝承 `chapter1/sky_ruins` |
| 5 `inscriptions` | 背中には崩れた町。三つの道の先に碑文 | 碑文を読む（西・東・水路、0/3） | 伝承 `chapter1/inscription_west/east/below` |
| 6 `heart` | 封印の奥で何かが脈を打つ | 心臓を止め、欠片を手にする | 伝承 `chapter1/heart_stilled` と `chapter1/sky_key` |
| 7 `return` | 欠片はほのかに温かい | 都へ戻り、語り部かイサナに見せる（どちらか一つ） | 語り部 `fragment3` かイサナ `c_fragment2` |
| 終わり | 残る三つはほかの巨神の中に | — | 経験値 200（段階の 310 と合わせて 510）、好感度（両方 +5） |

- **目的は伝承の書の記録で数える。** 碑文・心臓・欠片・岩鯨は伝承の書がすでに拾っている出来事なので、クエストは `Lore.state` を読むだけ。岩鯨の試練のコードには手を入れていない。同じ出来事を二か所で拾うと食い違うため。
- **順番を外しても詰まらない。** 伝承の記録は消えないので、先に背中へ行っていた人は、その段に着いたとたんに済む。先に岩鯨を見つけた人は、序 1・序 2・1・2 段を飛ばす（`skip_if`）。最後の段は語り部とイサナのどちらでもよい。
- **ピースフルでは 5 段で止まる。** 02 の決定どおり、ピースフルでは試練が封じられて碑文の奥へ進めない。難易度を戻せば続きから進む。
- 段の経験値: 序 1 が 20、序 2 が 20、1 が 30、2 が 30、3 が 60、4 が 60、5 が 90（計 310）。報酬は終わりの 200 と好感度だけ。心臓の報酬（02）が大きいので、クエストは道案内に徹する。

### 2.2 序盤の語り（序 1・序 2 と見聞）

序盤の拍子（野営地・足跡・足音・骨の丘・空の歌）の全文と順番は 17 の 11 章。ここには仕組みだけ。データを直接直す（生成スクリプトはない。伝承・17-10 の閉じ方）。

- **語り部の入口**: `shadow0`（メインが `follow_smoke`）、`shadow_first`（影のあとの初対面。`shadow2`→`shadow3` へ続く）、`shadow_wait`（影を待つ間、一度だけ。印 `wait_told`）。ループの「覚えているような」入口（`deja_vu*`）のあと、`first` の前。
- **道すがらの見聞**: 語り部の話題に「道すがら、気になるものを見た。」（`seen_menu`）、イサナに「道中で、妙なものを見た。」（`c_seen_menu`）。伝承が記されていて、まだ話していないものだけ並ぶ（印 `<話題>_told`）。語り部の話題の節は枠の高さの上限（210）のため、もとの「岩鯨を見た」「背中に町の跡」の話題も `seen_menu` に置く。
- **B7: イサナと会う（印 `met`、イサナ）までは、序盤のサブを出さない。** 言伝ての板の日替わり・週替わり（クエストの `unlock` に条件 `flag met`、`npc skyabyss:whale_chaser`。板では「閉じた」表示、手がかりは「村外れの旅人と話すと、受けられる」）、語り部の「ほかに、頼みごとはある？」（その先の板の話題・影の帳面・包み・白いところもまとめて閉じる）、語り部の「数え歌の続きが知りたい」。イサナ側の頼みは本人の話題なのでそのまま。`met` は会話を開いた時点で立つ（`DialogueService.open`）。ループで印が消えると、次のループでも最初は閉じる。
- 自己テスト `SELFTEST opening story`（`story/OpeningStorySelfTest`）。

### 3.4 見た目

素材: `docs/review/npc_roughs/`（比較シートと選定の表 `README.md`）。今のモデルは低ポリのメッシュ（15 の 9.6。語り部 A・イサナ A。`tools/install/install_lowpoly_ember_npc.py` が入れ、`LowPoly.enabled = false` で滑らかなボクセル版（15 の 4.5。語り部 B 頭巾・イサナ A つば広帽）に戻る）。語り部は頭巾の縁と白い髪の房、結んだ前掛け、イサナは広いつばの帽子とボタンの外套、背負い袋が、近くで見ても面の張りで読める。下の表は役の見た目の方針。生成: `tools/rough/npc.py`（画面の見本は `tools/rough/npc_ui_mock.py`）。

| | 選んだ案 | 特徴 |
| --- | --- | --- |
| 語り部 | A改（肩掛けの老婆） | 肩掛け・結縄・髷が一度に見え、「都の言い伝えを数える人」が読める。頭は 5 単位で首から前へ突き出し、上体を段ごとに前へずらして腰の曲がりを作る。眉・頬骨・鉤鼻・髷と簪・袂・組んだ手 |
| イサナ | A（長外套・広つば） | 背の袋（丸めた地図・鍋）と遠眼鏡のケースがシルエットで読め、「旅をしている」が一目で分かる |

- 立方体は 0.5 単位、重なりなし（`check_overlaps` が空）。テクスチャは 1 単位 = 2 画素（32px 密度）、面ごとの uv。光る所はないので発光層は付けない。
- 前かがみは骨の回転を使わず段のずらしで作った。GeckoLib はファイルの回転の X を反転して読むので、回転だとゲームで後ろへ反るおそれがあるため。
- 頭はコードで話し相手へ向ける（`NpcRenderer`）。上下は符号を反転して入れる（`PITCH_SIGN = -1`、ゲームで確認済み。左右の `YAW_SIGN` は体ごと向き直るため見分けられていない）。
- 肖像は 128×128 のドット絵（胸から上、光は左上の手前）。いまの低ポリの姿に合わせて一枚ずつ描き起こした（会話画面の肖像の仕様は 4.1、生成は `tools/gen/mobs/gen_portraits.py`）。表情 3 種（ふつう・笑み・沈む）。
- 話すとき右手が少し前へ出る（イサナ 26°、語り部 14°。`raise_r`）。

### 4.1 画面

### 4.2 しくみ（サーバーが決める）

- 会話の進み方はすべてサーバーが決める。画面は今の節を映し、選んだ番号を返すだけ（改造したクライアントが条件を飛ばせない）。
- 話しかけると、会話の `entries` を上から調べ、最初に条件が合った節から始める。
- 節に入ると: 節の結果（`do`）を起こす → クエストに「この節に入った」と知らせる（`talk` の目的）→ 条件に合う選択肢だけを送る。
- 選ぶと: 送ってきた節が今の節と同じか、選択肢が見せたものか、条件がまだ合うかを確かめてから、選択肢の結果を起こし、行き先へ。食い違えば今の節を映し直す（画面が返事を待ったまま止まらない）。別の NPC と話し始めたら前の NPC の「話している」を外し、節ごとに話している印を更新する。
- 行き先: 節の名前、`end`（閉じる）、`@entry`（入口を調べ直す。話題を選ぶ節へ戻るのに使う）。
- 一人に一つの会話。同じ NPC と二人が同時に話してもよく、それぞれの記録で分岐する。

### 4.3 データの形

```
data/<名前空間>/dialogue/<役>.json        会話 (役はエンティティの ID と同じ)
data/skyabyss/dialogue/<役>_free.json     自由なモードの足し書き (`"extends": true`)
data/skyabyss/dialogue/<役>_story.json    1 章の続きの足し書き
assets/skyabyss_npc/lang/{ja_jp,en_us}.json   会話・クエスト・画面の文
```

```json
{
  "npc": "skyabyss:storyteller",
  "entries": [
    { "if": { "type": "quest", "quest": "main_song", "stage": "return" }, "node": "fragment" },
    { "if": [ { "type": "loop", "min": 1 }, { "type": "remembers", "flag": "met" }, { "type": "not", "of": { "type": "flag", "flag": "met" } } ], "node": "deja_vu" },
    { "node": "menu" }
  ],
  "nodes": {
    "song1": { "face": "smile", "do": [ { "type": "flag", "flag": "song_heard" }, { "type": "lore", "entry": "prologue/counting_song" } ], "next": "song2" },
    "song2": { "options": [
      { "id": "curious", "goto": "song_curious", "do": [ { "type": "affinity", "amount": 2 } ] },
      { "id": "child", "goto": "song_child", "do": [ { "type": "affinity", "amount": -2 } ] } ] }
  }
}
```

| 欄 | 意味 |
| --- | --- |
| `entries` | 入口。上から調べ、最後の一つは条件なし（必ずどれかが開く） |
| 節の `face` | neutral / smile / grave（肖像の表情。指定が無ければ neutral。データ検証が未知の値を落とす） |
| 節の `do` | 入ったときの結果 |
| 節の `next` | 選択肢の代わりに「続き」（▼）。`options` とどちらか一方 |
| 選択肢の `if` / `do` / `goto` / `kind` | 出す条件、選んだときの結果、行き先、印（talk / quest / give / leave） |
| `text` | 文のキーを上書き（省略すると `dialogue.<名前空間>.<役>.<節>`、選択肢は `.<節>.<選択肢>`） |

- 文と構造のデータを直接直す（生成スクリプトはない）。会話の JSON、クエストの JSON、lang（日本語・英語）、この書類の 9 章の表を一度に書き出す（キーの書き間違いと、片方の言語だけ直し忘れるのを防ぐ）。文は別の名前空間 `skyabyss_npc` に置く（本体の lang と並行作業でぶつからないため。ゲームで読まれることは確かめた）。
- **足し書き**: 元のファイルに手を入れず、`"extends": true` のファイルで混ぜる。`DialogueManager` が読み込むときに、節を足し、入口を元の最後の入口（条件なし）の手前に足し、元の節の選択肢を指定の選択肢の手前に足す（`add_options`）。自由なモードの文は `assets/skyabyss_quest/lang`、1 章の続きは `assets/skyabyss_story/lang`。データを直接直す（生成スクリプトはない）。**この 2 つは書き出したあとの手直しと食い違っているので、再実行しない**（17-10 の閉じ方は  がデータを直接直す）。
- **章ごとの追加ファイル**: `dialogue/` の下ならどのファイル名・サブフォルダでも、`"npc"` と `"extends": true` を書けば同じ役に混ざる（`storyteller.json` のような大きな元には足さない）。例: `data/skyabyss/dialogue/ch2/storyteller.json`。複数の足し書きは場所の名前順に混ぜる。元（`extends` なし）の会話がないと「足し書きの元がない」と警告し、節の名前が元と重なっても警告して足さない。節の名前は `ch2_` のように章の頭を付けて重ならないようにする。自己テスト `SELFTEST arc` が合成した元と足し書きで、節・入口・`add_options` の混ざり方を確かめる。
- 話題の節の選択肢は、枠の高さ上限（210）を越えないよう、足すときは一つだけにして残りは別の節に分ける。

### 4.5 ループをまたぐ会話（「覚えているような」NPC）

器だけを作った。ループ本体（月の落下と巻き戻し）は M4。

| 項目 | 決まり |
| --- | --- |
| ループの回数 | サーバー全体で一つ（`WorldLoop`、オーバーワールドの SavedData `skyabyss_npc`）。今は 0。M4 は月が落ちたときに `WorldLoop.advance(server)` を呼ぶ |
| 巻き戻すもの | その人と NPC の、このループの会話の印・好感度・話した回数（01 の表「NPC の状態と会話フラグ」は巻き戻る） |
| 残すもの | 印は消える代わりに「記憶」（echoes）へ移る。留まる者に向けた微かな覚えとして、条件 `remembers` で読める |
| その場にいなかった人 | 次に入ったときに追いつく（記録の `loop_seen` と比べる） |
| クエスト | `loop_reset: true` のクエストのうち、まだ終えていないものだけ最初に戻す。今の 3 本はどれも `false`（伝承の記録で数えるので、戻してもすぐ追いつく） |
| セリフ | ループ 1 回目以降の最初の会話で、語り部は「前にも、その顔を見た気がするね……いや、年寄りの気のせいだ」、数え歌を聞いていた人には「あの歌の続きを聞きに来たんだろう……どうしてそう思ったんだか」。鯨追いは「どこかで会ったか？」。一ループに一度だけ（会うと印 `met` が立つ） |

伝承の書の「白紙の帳面」の一行（「次は、もっと早く気づけるように」）と、語り部の「この字、どこかで見た気がする」が、同じ方向をほのめかす。核心（留まる者がなぜ覚えているか）は言わない。ループで印が記憶へ移るのは、何を覚えていそうかは前のループで何を話したかで決まるのが自然なため。M4 が回数を一つ進めるだけで動く。

## 6. クエストのしくみ

### 6.1 データの形

```
data/<名前空間>/quest/<名前>.json
```

| 欄 | 意味 |
| --- | --- |
| `category` | main / sub |
| `order` | ログの並び |
| `giver` | 依頼主の役（ログに「依頼: 語り部」。板のものは「言伝ての板」） |

| `loop_reset` | 月のループで、まだ終えていなければ最初に戻す。今のクエストはどれも `false`（伝承の記録で数えるので、戻してもすぐ追いつく） |
| `stages` | 段階の並び。`id`、`mode`（all = 目的をすべて、any = どれか一つ）、`objectives`、`skip_if`（真なら着いたとたんに済ませる）、`xp`（段階を済ませた経験値）、`do`（済ませたときの結果） |
| `reward` | `xp`、`items`、`affinity`（役 → 量）、`do`。品には `name` / `lore` / `token` / `optional`（ほかの担当が後から登録する品）を付けられる |
| `repeat` | `"daily"`（オーバーワールドの日。夜明けで替わる）、`"weekly"`（7 日）。6.5 節 |
| `board` | 言伝ての板に出す（7.3 節） |
| `min_stage` | 受けられる個人の段階。ログと板で「一つ先」を伏せて見せるのにも使う（参加者へも送る） |
| `unlock` | 段階のほかの条件（サーバーだけ）。板に出すものに使う |
| `chapter` | 所属する章の ID（`prologue` / `titan_whale` / `titan_tide` / `titan_storm` / `titan_ember` / `chapter2` …。`Chapters.id()`）。省くとどの章にも属さない。知らない ID は読み込みの警告になり無視する。参加者へも送る。進行には関わらない（ログの見出しと右の頁の章名だけ） |

- **追加のクエスト**: `data/<名前空間>/quest/` の下ならどのファイル名・サブフォルダでも読む（`QuestManager` が全部を読む）。章ごとの担当は、大きな既存のファイルに足さず、`quest/<章>/<名前>.json` のような新しいファイルで足す。ID は `ch1/foo`（サブフォルダ込み）、文のキーは `quest.skyabyss.ch1.foo.title` のように `/` が `.` になる。メイン 5 本と一部のサブ（`sub_tide_watch`・`sub_warm_coal`）には `chapter` を入れてある。

| 目的 `type` | 欄 | 数え方 |
| --- | --- | --- |
| `talk` | `target`（役）、`topic`（節） | その NPC の会話でその節に入った（`topic` を省くと話せば何でも） |
| `kill` | `targets`、`count`、`radius` | 倒した人は距離を問わず、ほかは `radius`（既定 32）以内にいた人（倒れて復活を待つ人も含む）。取り消された死亡は数えない。パーティの仲間も数える（6.7 節） |
| `collect` | `target`（アイテム）、`count` | 持ち物の数（1 秒ごと。減れば戻る） |
| `lore` | `targets`、`count` | 伝承の書に記された数（既定は全部） |
| `visit` | `target`（ディメンション） | そこに入った（一度満たせば戻らない） |
| `near` | `targets`（生き物）、`radius` | 近くにいた（2 秒ごと。一度満たせば戻らない） |
| `signal` | `target` | 会話の結果やコードの `Quests.signal` |
| `condition` | `if` | 条件が真 |
| `turn_in` | 品（ID か `#タグ`） | 品を板（依頼主が NPC ならその人）で納める。手持ちの数はログと左の表示に出すが、納めるまでは済みにしない |
| `wear` | `targets`（品。防具）、`count`（既定は全部） | 防具の枠に着ている種類の数（脱げば戻る。一章の鉄の跡「鉄の防具を作って着よう（2/4）」） |
| `herd` | 生き物、`count`、`radius`（既定 10） | 受けた場所（板）の `radius` 以内にその生き物が `count` 頭。本人が 32 ブロック以内にいるときだけ数える |

- 目的の `party`（既定 true。`false` で本人だけ）、目的・条件・結果の `token`（品の印。`CUSTOM_DATA` の `skyabyss_quest`。印のある目的は同じ印の品だけを数える。語り部の包みを、ただの革で代えられない）。
- 記録には、段階ごとに `cycle`（受けた周期）・`origin`（受けた場所）、全体に `claimed`（払った周期）。
- 文のキー: `quest.<名前空間>.<名前>.title` / `.summary` / `.done`、段階の書き付け `.<段階>.journal`、目的 `.<段階>.<目的>`。

### 6.2 進み方

- 段階の目的が満たされたら（`skip_if` が真でも）、段階の結果と経験値を渡して次へ。次の段階の「状態で決まる」目的（伝承・持ち物・場所・条件）は着いたとたんに調べ、満たされていればまとめて送る。
- **経験値と報酬は一人一回。** `Growth.discover` の鍵（`quest:<クエスト>:<段階>`、`quest:<クエスト>`）で、コマンドでやり直したり、ループで戻ったりしても二度は渡さない（04 の discover と同じ流儀）。経験値は `Growth.addXp`（画面に「+30 雲の下の歌」）。
- 知らせ: 始まった・進んだ・終わったときに、右上に小さな札（伝承の書の羊皮紙と見分けられる暗い石板の色。メインは金、サブは青緑の縁）とアメジストの小さな音。始まったときと終えたときはチャットにも一行（前進の淡い青）。初めてのクエストでは「U キーで、クエストログを開ける」。
- 報酬の品は mod の素材（共鳴の欠片・鍔石など。03 の装備の釣り合いに触れない）。

### 6.3 クエストログ（U）

技の画面の K とぶつかるため U にした。

| 部分 | 中身 |
| --- | --- |
| 左 | 一覧: メイン（金）、サブ（青緑）、終えたもの（灰）。それぞれの中は、`chapter` 欄のあるクエストを章ごとの見出し（「· 一章　岩鯨」。章の番号順、章のないものが先）で分ける。見出しを押すと、その下の最初のクエストを開く。追跡中に ▸。一つ先の段階で開く一度きりの頼みは、「一章のあと」の見出しの下に「？？？」で数だけ出す（巨神の名や心臓は書かない）。二つ先は出さない。長くなったらホイールで送る（▲▼。選んだ行は見える所へ送る） |
| 右 | 題、章名（`chapter` 欄があるとき）、依頼主、今の段階の書き付け（言い切らない一人称のメモ）、やること（■ 済み / □ まだ、数のあるものは 2/3）、何段目か、報酬。**終えたもの**は: 題、章名、依頼主、受けた日と終えた日（「2 日目に受け、4 日目に終えた」。ゲームの総 tick から）、終わりの書き付け（`.done`）、やったこと（段ごとの目的を ■ で順に。どれか一つの段は「または」でつなぐ）、「このクエストは終えた。」、受け取った報酬（`quest/QuestDoneView`） |
| 下 | 「知ったことは、伝承の書に。」（ログは「やること」、書は「知ったこと」）。追跡する / やめる の釦 |
| 操作 | クリック、↑↓、ホイール（左の一覧・右の頁）、U か Esc で閉じる |

目的の数は「（1/」「3）」と行をまたいで切れないようにする（`QuestHud.wrapWithCount`。ログも同じ関数）。

### 6.4 左の追跡表示

成長の表示（Lv とバー）の下に、追跡中のクエストの題と、まだ済んでいない目的だけを小さく出す（どれか一つの段階は「または」でつなぐ）。位置は `QuestHud.y()`: 列の上端（25）＋技の段（`SkillHud.rowsBelowXpBar`）＋「+経験値」の列 4 行分の下（マナの段や「+12」の列と重ならない）。クライアント設定 `growthHudPosition` が経験値バーの左のときは、クエストの追跡が左上の一番上へ上がる。メインは始まると必ず追跡し、サブは何も追跡していないときだけ追跡する。終えたら次の進行中のクエスト（メインが先）へ移る。ログの釦でやめられる。F1・F3・ログを開いている間は出さない。

### 6.5 繰り返し

| 項目 | 決まり | 理由 |
| --- | --- | --- |
| 型 | `repeat: "daily"`（夜明けで替わる）、`"weekly"`（7 日。ループの本体ができたら回数に替える。`Repeats.cycle`） | 週替わり |
| 板に出す日替わり | ワールドの日数で決まる抽選で `Board.DRAW` = 5 つ。世界の進みの一つ先の段階のものまで混ぜる。週替わりは全部出す | 同じ日は全員が同じ顔ぶれを見る。先があると分かる |
| 一日の枠 | 日替わりは一人一日 `Board.QUOTA` = 3 つ。週替わりは種類ごとに週に一度で、枠に数えない | 枠なしだと周回の作業になる |
| 受けたまま日が替わる | 消えない。いつでも続けられる | 急がせない。夜回りを夜明け前に受けても損をしない |
| 報酬 | 周期ごとに一度。最後に払った周期を記録に残す（`QuestLog.claimed`）。記録を消して同じ日に受け直しても二度は出ない | 日ごとの鍵は増え続けるので、クエストごとに一つの数にした |
| 経験値 | 報酬でだけ渡す（段階の経験値は一人一回の鍵なので、繰り返すクエストには書けない。読み込みで弾く）。ふつうの決まり（上限・推奨 +3 からの減り）を通る | 上限にいる人は品だけ受け取る |

### 6.6 解放

- 解放は個人の段階（止めた心臓の数）と伝承の記録で決める。物語を追い越さない（潮殻は「干潮に岸へ寄るものを見る」までで、背中へ入る目的は作らない。次の巨神の敵や心臓を目的にしない。自己テストで確かめる）。
- 報酬は経験値（レベルの上限の内側）、素材（岩鯨の鱗片・共鳴の欠片・結晶を少し）、伝承、見た目の小物（名前と説明の付いたバニラの品）だけ。装備は出さない（物語より強くしない）。
- 仲間がいないと終えられない目的はない（一人でも終えられる）。
- 段階のほかの条件は 4.4 節の `stage` / `stilled` / `world_stage`。

### 6.7 マルチ

| もの | 決まり |
| --- | --- |
| 記録 | 人ごと（10 章）。二人が同じ頼みを同時に進めても、会話も品も別（自己テストで二人同時に「火のそばへ」を通す） |
| 倒す（`kill`） | 本人と、倒した場に居合わせた人（半径の内）。加えて、居合わせた人のパーティの仲間で、経験値の分け前と同じ条件の人（64 ブロック以内、同じ巨神の背中なら距離を問わず、10 レベルを超えて低い人は除く）。`party: false` で切れる。仲間は party の目的だけ一度（`QuestEvents.credit`） |
| 合図（`signal`） | 試練の踏破は、居合わせた人と仲間。空の影・干潮・旅は人ごと（`party: false`。その目で見ることが目的なので） |
| 集める・納める | 人ごと。仲間の持ち物は数えない |
| 連れ戻す（`herd`） | 受けた板のそばにそろっていれば、誰の羊でもよい |
| 板の顔ぶれ | ワールドで一つ |
| 枠 | 人ごと。仲間が終えても、自分の枠は減らない |
| 仲間が受けている | 板の札に「仲間 N 人も」（オンラインの仲間だけ）。押し付けない |

### 6.8 備えの頼みと旅の覚書（章の導きの基盤。`guide/`。21 の 1.4）

**備えの頼み**: 各章（一〜四章）に 3 本。章の担当（二章 P11、三章 P15、四章 P19）は、次の規則でファイルを足すだけでよい（`PrepQuests`）。**一章は 34 の支度の段（メインの段 `ch1/trail_*`。下の「一章の支度の段」）に置き換えた**。二〜四章も 34 の段の名前に替えるときは、`PrepQuests` の章の表（`CHAPTER_IDS`）に一行足し、その 3 本はメイン（`category` = `main`）にする。

| 決まり | 中身 |
| --- | --- |
| 置き場・ID | `data/skyabyss/quest/ch<n>/prep_gear.json`（身ごしらえ）、`prep_blade.json`（刃を研ぐ）、`prep_pulse.json`（鼓動を聞く）。n = 2〜4（一章は `ch1/trail_iron`・`trail_blade`・`trail_shield`）。ID は `ch<n>/prep_<kind>`、文のキーは `quest.skyabyss.ch<n>.prep_<kind>.title` など |
| 必須の欄 | `category` = `sub`、`chapter` = その章の ID（一章 `titan_whale`・二章 `titan_tide`・三章 `titan_storm`・四章 `titan_ember`）、`start_when`（章の頭にクエストログへ自動で出る）。`repeat` と `board` は付けない。違えば読み込みの警告（`QuestManager.loadErrors`。`PrepQuests.validate`） |
| 順番 | ふさがない。どれから受けても終えてもよい（ログの並びは `order`） |
| 合図 | 3 本が終わったとき（どの順でも）、その人へ `ch<n>_ready` の合図（`Quests.signal`）を一度だけ送る（人ごと。`Growth.discover` の鍵 `prep_ready:<n>`）。3 本の定義がそろっていない章は合図が出ない（中身のない章） |
| 読み方 | 条件 `{"type":"prep","chapter":n,"min":k}`（k 本以上。`min` を省くと 3 本）。コードは `PrepQuests.done / ready / atLeast / groupAtLeast`（`groupAtLeast` はオンラインの仲間まで見る。一章の岩鯨の降下には使わない（見たら降りる。17 の 2.8）） |
| 覚書 | その章の 3 本のどれかを受けたとき、その章の旅の覚書を人ごとに一度渡す。知らせの文は「支度の段が始まった。手引きの旅の覚書（一章）が荷物に届いた」（`message.skyabyss.notes.given`）で、頼みの札のあとに出る（単独で出さない。first_hour_log B-7） |

| 結果 | 会話の結果 `give_notes {chapter}`: 覚書を渡す。受け取り済みでも、持っていなければ渡し直す（職人の補充用） |

**旅の覚書**（`wayfarer_notes`。`WayfarerNotes`）: 章ごとに 1 冊の薄い手帳。1 つのアイテムで、章（0 = 序章、1〜4）は品の欄 `skyabyss:notes_chapter` に持つ。名前は「旅の覚書（一章）」。右クリックで手帳の画面（`WayfarerNotesScreen`）を開く。

### 8.5 NPC の頭の上の印（`npc/NpcMarkers`、`client/npc/NpcMarkerClient`）

話しかけると何かが起きる NPC の頭の上に、**その人にだけ見える**印を出す（RPG の「！」「？」）。計算はサーバーが人ごとに、会話のハブの印（`DialogueService.visibleOptions`。8.2 節）と同じ規則で行い、1 秒ごとに、64 ブロック以内の NPC のうち印のあるものだけを、変わったときにその人にだけ送る（パケット版 `npcmark-1`）。話しても何も起きない（入口が定型のあいさつだけ）なら印は出ない。

| 印 | 見た目 | 出る条件（上ほど優先） |
| --- | --- | --- |
| `READY_MAIN` / `READY_SIDE` | 「?」 金 / チェックの巻物（青緑） | 進行中のクエストの**最後の段**が、この人に話すこと（報告）。または、この人が依頼主で、納める品（`turn_in`）が手持ちでそろっている |
| `NEW_MAIN` / `NEW_SIDE` | 「!」 金 / 巻物（青緑。サブは「!」を使わない） | 進行中のクエストの**次の段**が、この人に話すこと（まだ聞いていない話題）。または、会話の入口の節にこの人からの新しい頼み・渡す品がある（ハブの金の印と同じ判定。メインの依頼主なら金、そうでなければ青緑）。「新しい頼み」と数えるのは、先をたどると実際にクエストを始める・品を渡す・品を納める・板を開く結果があるものだけ（`DialogueService.offers`）。頼みに見えて何も起きない選択肢は、金の印にも「!」にもしない。言伝ての板を開く選択肢は話題の印 |
| `CHAT` | 吹き出し（淡い色） | 入口が定型のあいさつでなく、その人がまだその節を開いたことがない（`NpcBonds` の `seen`。開くと消える。月のループで戻る） |

見た目: 16×24 のドット絵（メインの「!」「?」・サブの巻物とチェックの巻物・吹き出し。暗い縁取り・明るい縁と影。`tools/gen/mobs/gen_npc_marker_icons.py` が `textures/gui/npc_marker/` に書く）と、色つきのやわらかい光。近くでは高さ約 0.65 ブロック。遠いほど大きくするが 2.4 倍まで（距離 ÷ 10、下限 1）。ゆっくり上下し（周期約 2.5 秒）、新しい・報告の印は光と大きさがやさしく脈打つ。メインは金の「!」「?」、サブは青緑の巻物。

- メインは金、サブは青緑（クエストの札と同じ色）。「?」はゆっくり脈打つ。印のない NPC には何も出さない。
- 見え方: 遠いほど大きく描き、64 ブロックで消える。16 ブロックまでは壁越しでも見える。それより遠くは、頭が見通せるときだけ（クライアントが 5 tick ごとに視線を調べる）。場面・画面（会話を含む）・F1・目覚めの暗転では描かない。設定 `npcMarkers`（既定 ON）で消せる。
- 実装: 印の計算 `NpcMarkers.of(player, npc)`、会話の入口を開いたら `Bond.seen` に節を足す（`DialogueService.open`）。描画は世界の描画の段（`AFTER_TRANSLUCENT_BLOCKS`）に、画素の絵（5×8 の「!」「?」、3×3 の点。縁は暗い色）をカメラの向きの板で描く。
- 自己テスト `npc`（`NpcMarkerSelfTest`）: 人ごとに違う（一人の進みがもう一人の印を変えない）、報告の「?」、ハブの印との一致、定型だけなら印なし、点は開くと消える（別の人には残る）、頼みのあるハブは「!」で頼みの出ないハブは印なし、パケットの詰め替え、日英の lang に「探索しつつ」などが残っていない。
- 18 の 8.4 節に、章の札と更新の音。
- 都の施設の係の人（3.7）は、頭の上にいつも**施設の印**（16×24 の淡い骨の色。金槌・旗・寝台…。`textures/gui/npc_marker/fac_<役>.png`）を出す。誰にでも同じに見え、32 ブロックまで、上下しない。上の表の印があるときは、施設の印の上に重ねずに出す（`FacilityIconClient.QUEST_LIFT`）。

## 14. 設計判断の理由

| 判断 | 理由 |
| --- | --- |
| 最初の二人を「語り部」と「鯨追い」にした | 都の言い伝え（05 の頁: 数え歌・峰・見る者）を語る人と、1 章の岩鯨へ導く人を分けると、「怖い話を聞く → 確かめに行く」の流れが自然になる。語り部は地上に残る人、鯨追いは空へ惹かれる人で、物語の「天と淵」の対にもなる |
| 語り部は都の大鐘楼、鯨追いは鯨見の町 | 大陸の物語の入口（42）。町が章の入口なので、鯨を追う人は鯨の見える町にいる |
| NPC は傷つかない | クエストの相手が死ぬと進めなくなる。叩いたときは嫌がって好感度が下がる（反応はある）。倒せるが翌朝同じ場所に戻る案は見送った |
| 目的を伝承の書の記録で数える | 伝承の書がすでに碑文・心臓・欠片・岩鯨を拾っており、記録は消えない。順番を外しても詰まらない |
| 会話はサーバーが進める | 条件（クエスト・持ち物）を画面側で判定すると、改造で飛ばせる・同期がずれる |
| 会話とクエストはデータが正 | 最初は生成スクリプトから書き出したが、そのあとデータを直接直してきたので、生成スクリプトは消した（書類にも書き写さない） |
| 文は言い切らない | 01 の「1 章ではつながりを説明しない」。語り部は話をそらし、鯨追いは自分の感覚しか言わない（欠片を見て「心臓」とは言い当てない）。核心（巡礼者・心臓・留まる者）は名前すら出さない |
| ループの記憶を「印が記憶へ移る」形にした | 4.5 節 |
| 経験値と報酬は一人一回 | 会話のくり返し、コマンドでのやり直し、ループで稼げないように |
| メインの報酬は経験値と好感度だけ | 心臓の報酬（02 の 6 章）が大きいので、クエストは道案内に徹する |
| 序章の言い伝え 4 項目を頁でも話でも記す | 頁の運だけに頼らず、サブ「数え歌のつづき」を必ず終えられる |
| クエストログのキーは U | K は技の画面が使っている |
| 自由なモードの日替わりの受け口は言伝ての板 | NPC がいない所でも受けられる。板だけにすると NPC の話題が減るので、語り部の「頼みごと」から同じ画面を開く |
| 05 から 07 を分けた | 05 は伝承の書だけで 490 行あり、NPC とクエストを足すと読みにくい |
