## 2. 点と基礎

### 2.1 技の点

- **1 レベルにつき 1 点**（Lv 1 で 1、Lv 50 で 50。`SkillRules.pointsForLevel`。追加の点は転生の報いだけ）。職ごとに別に数える（`SkillData.nodeSpent`）。
- 木 1 本の節の合計は 95〜115 点（節 63〜81）。Lv 50 で取れるのは半分弱なので、型 1 つを深く取るか、2 つを浅く混ぜるかの選びになる。
- 目安: 使う技 4 本は 9〜14 点 (Lv 9〜14)、型の要は最短 13〜16 点 + 型の点 20 (Lv 23〜27)。木 1 本は 95〜115 点。
- 振り直しは今の職の木だけ戻す（ほかの職の木・淵・前世はそのまま。Lv 15 までどこでも無料、あとは炉か師範のそばで結晶 1）。型の保存は職ごとに 2 つで、枠・刻印と一緒に**木の取り方**も保存する（戻すとき点が足りなければ断る）。

### 2.2 基礎（ステータス）

- 筋力・敏捷・精神・耐久の 4 つは残す。効き目の式は 04 の 4 章のまま。
- 上げ方は木の**基礎の節**だけ。1 節 = 1 点で +4（木の中で主な基礎に 40〜70 ぶん、副の基礎に 24 ぶん置く。主な基礎は幹と三つの型のどこを進んでも深淵の武器の要求値 24 に届くように置く）。レベルでは上がらない。今の職の木から導いた値を `SkillManager.refreshStats` が成長の記録へ写す（節を取ったとき・職を替えたとき・ログインのとき）。上限は 100（`GrowthRules.STAT_CAP`）。
- 閾値の節は、その基礎が N 以上のときだけ効く（例: 盾の守り手「岩の肌」= 耐久 24 で防具 +2）。N はその木の基礎の節だけで届く値にする（主 20〜40、副 20〜24）。
- 基礎は装備の要求値にもなる（03 の 6.5。`GearRequirement`）: レア以上の職の武器は、由来の章ごとに主な基礎 10／14／18／22（深淵 24）。届かなければ近接の攻撃力が半分・木の印が効かない。

### 2.4 節の種類

木は `assets/skyabyss/skill_tree/<職>.json`（jar の中。サーバーとクライアントで同じ）。戦士は手書き、ほかの 5 職は `tools/gen/skill_tree/gen_trees.py` が書く（節の文も一緒に lang へ）。読み込みと決まりは `rpg/skill/tree/`（`AbilityNode`・`AbilityTree`・`AbilityTrees`・`NodeEffects`）。

| 種類（`kind`） | 点 | 中身 |
| --- | --- | --- |
| `active` 使う技 | 2（幹の根は 1） | R・G・V・Z に置く技。**取れるのは 4 本まで**（`SkillRules.BASE_SLOTS`。5 本目は `ACTIVES_FULL`）。戦士 7 本、呪術師 5 本、ほかは 5 本 |
| `rank` 段 | 1 | その技の段 +1（`<技>_2`・`_3`。常に効く技の段もこれ） |
| `passive` 常に効く技 | 2 | 今の常時の技（返し刃・岩の構え …） |
| `keystone` 要 | 3 | 要の技（守り石の約束 …）。型の点 20 で開く |
| `rune` 技を変える節 | 1〜2 | 今の刻印。同じ技の刻印は一つだけ（自動で排他） |
| `stat` 基礎 | 1 | 基礎 +4 |
| `threshold` 閾値 | 1 | 基礎が `at` 以上のとき `effect` が効く |
| `effect` 常に効く数 | 1〜2 | `effect` の鍵と値（下）。排他は `excludes`。型の点で開く枝の奥の節は `arch_points` |
| `trait` 型の要（古い鍵石） | 3 | 鍵石 6 つ（砦・硝子の刃・満ち潮・灰の契り・独り弦・疾風の舞）をそのまま型の要に |
| `mutation` 変異 | 2 | 技の変異（`Mutation`）。極めた技の枝の奥。取るとき巨神の核 1 と欠片 3 を払う（`SkillExtOps.payMutation`。一度払えば `SkillData.mutations` に残り、振り直し後の取り直しはただ）。効くのは節を取っていて技を極めているあいだ |

- `effect` の鍵（`NodeEffects`）: `armor` `knockback` `move` `attack_speed` `mana`（属性）、`attack` `projectile`（与える傷の割合）、`skill_power` `cooldown` `mana_cost` `regen`（技）、`damage_taken` `damage_taken_still`（1 秒止まってから）`fire_resist`（受ける傷）、`big_target`（大きな相手への技の傷）`lifesteal`（近接の吸い。1 回 1❤ まで）`low_hp_armor`。
  技ごとの鍵: `cooldown@<技>` `mana_cost@<技>` `power@<技>`（その技だけの再使用まで・マナ・力。`SkillBuild` で全体の値と足し、上限は同じ）。マナ: `mana_hit`（近接で当てるたび。0.6 秒に一度。武器の特性マナ吸収と足す。`AffixEvents`）`mana_kill`（敵を倒したとき。`SkillEvents.onDeath`）。`cd_kill`（敵を倒すたびに、発動スキルの再使用までを縮める秒。`SkillEvents.onDeath`）。
- 前提 `requires` はどれか一つ取っていればよい（線）。排他 `excludes`。**型の点** = その型（`arch`）の節に使った点の合計。
- **2026-11-02 の直し**（声「思ったような選択ルートにならない」「線が機能してない」「点 20 いるやつとか、選べない」「わかりにくい書き方」）:
  - 型の要の門は、本当に取れる点に合わせた（`gen_trees.py` の `reachable`: 同じ技の刻印は一つ・排他・使う技 3 本の中での最大 − 2）。枝の根が同じ技の刻印三つの型（弓の貫き・暗殺者の舞いと孤風・呪術師の満ち潮と引き潮・鍛冶師の熾火）は一本の枝しか進めず 20 に届かなかった。いまは 10〜18。全部の節が 30 点以下で届くことを全探索で確かめた。
  - 線は節の真ん中どうしをまっすぐ結ぶ（前の折れ線は同じ行の横の線が重なって、どれがどれにつながるか読めなかった）。両方取れば金、手前を取れば明るく、マウスの下か選んだ節につながる線は太い水色。同じスキルの変化を取って閉じた節には赤い ×。説明に閉じた理由（どの変化を取ったか・型にあと何 SP か）。
  - 言葉: 点 → スキルポイント（SP）、使う技 → 発動スキル、常に効く技 → 常時スキル、型の要 → 奥義、技を変える → スキル変化、基礎 → 能力値、閾値 → 条件つき効果、待ち → 再使用まで、キー → 発動キー。起こすときの「使うキー」は実際の割り当てのキー名で出す。
- **技ごとの節**（2026-11-02 の声「スキルツリーとかももっと Wynncraft に寄せたい。クールダウン減少等々」）: Wynncraft の木の「Cheaper Bash」（その技のマナ −）や技の待ちの短縮のような節を、六職とも同じ決まりで足した（`gen_trees.py` の `wynn_nodes`。戦士の手書きの木にも一度だけ足す）。
  - 幹: 根の技の軽減（マナ −25%）を (2,1)、早さ（再使用まで −20%）を (6,1)。幹の二つ目の技の軽減を (3,3)、早さを (5,3)。どれも 1 SP。
  - 型: 型の一番下の行の下（5 職は 11 行、戦士は 12 行）に三つ。左から型の技の軽減（幹の技ですでにあるときは「冴え」= その技の力 +12%）、マナの節（近接の職 = 戦士・暗殺者・鍛冶師は「打ち手の泉」= 当てるたびにマナ +1、ほかは「仕留めの泉」= 倒すとマナ +2。2 SP）、型の二つ目の技の早さ。前提は型の一番下の行のどれか。
  - 武器の特性マナ吸収（`AffixType.MANA_STEAL`）と合わせて、殴ってマナを貯める武器と技の武器を持ち替える遊び方を作る。
- 格子は幅 9（x 0〜8）。幹は x 4 の 0〜3 行（根の技・基礎 2・常に効く技 2・二つ目の使う技・枝へのつなぎの基礎 3）、型は左 (0〜2)・中 (3〜5)・右 (6〜8) の 4〜10 行。型の要は 9 行目。
- 取る決まりの検め（`SkillData.canTake`）: 知らない節 / もう取った / 前提 / 排他 / 型の点 / 使う技 4 本 / 段の上限 / 点。記録は職ごとの「取った節の集合」（`SkillData.nodes`）で、技の段・刻印・鍵石はそこから導く（`applyNodes`）。読み込み時の検め（`sanitizeNodes`）は、知らない節と前提の崩れた節を外す。
- 節の値は 4.1 のまとめた形（型の中の常に効く数は 10〜25%）。技の倍率は ×1.2〜×1.8。回復・無敵の節は作らない（04 の 7.7）。

### 2.5 技の待ちとマナ（2026-11-02。00 の 343 A）

- どの技も待ちを 0.65 倍（`SkillRules.COOLDOWN_SCALE`。全体の待ちの最短は 0.5 秒）、マナを 1.15 倍（`MANA_SCALE`）。主の大技のあとの隙（3 秒、与える傷 ×1.6。47 の 2.1）に技を重ねられ、打ち手の泉・マナ吸収で回す遊びにする。長い戦いはマナで縛る（`BuildsSelfTest` の「一本だけの瞬間の上限」は 0.45 / 0.65 まで）。

### 2.6 型の溜まるもの（2026-11-02。00 の 342 A・345）

声「戦っていて楽しいようなスキル回しとかできる？」。Wynncraft の型の仕組み（印・堕落などのゲージ）のように、型ごとに一つ「溜まるもの」を持つ。ある技（や近接・矢）で溜め、別の技で放つので、技の順番に意味が出る（`rpg/skill/Gauges`）。

- 出る条件: 今の職の木で、その型に 8 点以上使っている（二つ以上なら点の多い型）。出たときに一行の知らせ。技の木の説明の欄に、六つの型の力の行。
- 見せ方: マナの帯のすぐ上の細い帯（`VitalsHud.drawGauge`）。小さい数は点、岩の重み・炉の熱・孤りは帯。満ちると脈打ち、満ちた瞬間に白く光る。水の中で空気の帯が出ている間は描かない。
- 空に戻る: 死んだとき・職を替えたとき（型が変わる）。開発用 `/skyabyss skill gauge <人> <型> <値>`（`off` で点の決まりに戻す）。自己テスト `gauges`。

### 4.1 まとめた節と、動きが変わる型の要（2026-11-04）

声「技の木の節の効果が小さい（中央値 +5%）。一つ取っても違いが分からない」。鍛冶師の木で手本を作り、ユーザーの「強いまま広げる」で六職すべてに広げた。

  - 型の中の能力値の節は二つで一つに（除いた節を前提にしていた節は、除いた節の前提へつなぎ直す）。残りは +8（2 SP）。幹の節はそのまま。

## 5. 画面

- K の画面（`SkillScreen`）は、今の職の木だけを出す（左のつまみは今の職と、転生後の淵・前世）。盤は格子（`GRID` 34、節 22px。ドラッグ・ホイール・右で戻す）。線は前提（両方取っていれば明るい）。取れる節は明るく、点が足りない節は明るいが「n点」が暗い、前提の無い節は暗い。節の下に点（基礎は +4、段は +1）。使う技の節には菱形、排他のある節には赤紫の点。盤の下に型の名前と点。
- 右の欄: 節を選んでいなければ木の説明・使う技の数（n / 4）・型の点 3 つ・基礎 4 つ。技の節はいつもの技の説明に「種類・点・型・前提・いま取れるか」を添える。ほかの節は種類と点・中身・前提・排他・型の点・いま取れるか。釦は「取る」（節を取る。`SkillNodePayload`）。
- 試着（画面だけの写し）は節でも使える。型の保存 2 つ・振り直し・変異と紋のページはそのまま。
- J（`GrowthScreen`）は読むだけ: レベル・経験値・職・基礎 4 つとその効き目・記憶の断片。振り分けの釦は無い。
- 職の間: 3 章。
