## 1. 共通の決まり（全担当）

### 1.0 シリーズの見た目の統一（一番大事）

- 同じシリーズ（祠の始めの武器、同じ土地・同じ帯の品、同じ巨神の品など）の品は、並べたときに一揃いに見えること。これが全ての決まりの中で一番大事。
- そろえるもの: 素材と色（主・副・差し色）、継ぎ目の隠し方、握りの作り、光る見せ所の作り、装飾の細かさ（1.7）。職ごとの違いは骨格（2 章）と、光の色ぐらいに留める。
- 新しい品を作るときは、同じシリーズの決まった品と並べた画像を必ず作り、そろって見えるかを確かめてから見せる。
- 作り直す品は、前の形（前のゲームの模型・設定の絵）の特徴も尊重する。ただしシリーズの統一の方を優先する。
- **シリーズは素材ごとの色の段階（ランプ）を共通にする。** 素材ごとの色の段階はシリーズの設計ファイルの `lib.RAMPS.update({...})` に一度だけ書き、シリーズの品はその色だけで塗る（品ごとに変えない）。祠の 6 品だけは古い素材シート（`tools/models/shrine_series_tiles.png`）のまま。
- 祠の始めの武器のシリーズ（2026-11-17 に杖・剣・鎚で決まった）: 流木・木の柄、緑青の青銅、継ぎ目と握りを締める金の帯・輪、赤い紐の握り、見せ所の光る石（星の空色。鍛冶師は火の橙）を一つ。細かさは杖・剣・鎚と同じ。
- あいだの塔のシリーズ（神器。2026-11-20 にユーザーが決めた。書類 54 の 2 章）:
  - 色の段階は `tower_bold.py` の `tw_*`（白の大理石・金・淵の黒い石・夜の紫・紫の光・天秤の光）だけを使う。
  - 白黒は上下で割る。先の側（頭・刃先・上の弓腕）が天の白、根元の側が淵の黒。境に天秤の印の台（金の四角い台＋天秤の光の菱）を一つ置く。
  - 金は帯 3 か所（柄の輪は数えない）・先の尖塔・天秤の台だけ。鍔・角・爪・鈴などの大きな部品は、境より上なら白、下なら黒の石にする。
  - 光は 2 つ: 天秤の光の菱 1 つと、黒い側の紫 1 つ。浮く欠片（魔法使いだけ）は光らない石。
  - 柄は夜の紫に金の輪。

### 1.1 一番の決まり: 一目で種類がわかる

- **黒い影だけ（32 画素の大きさ）で、何の武器かわかること。** 鎚は鎚に、弓は弓に見える。飾りは種類の影を壊さない。
- 種類の影（下の 2 章の「骨格」）が全体の量の 7 割以上。飾り・光・奇抜な部品は 3 割まで。
- 見せる前に担当が自分で確かめる: 影だけの絵（単色で塗りつぶした正面）を撮り、種類を言い当てられるか。言い当てられなければ直してから見せる。
- 例（2026-11-17 の祠の鎚 C）: 頭が炉の形で、上に煙突と炎が立った。頭が縦長になり、影が「棒の上の角灯」に見えて鎚に見えなかった。鎚の頭は横長で、打つ面が影に出ていなければならない。

### 1.3 進め方

1. 担当が品の設定（51・43・各巨神の書類）と、同じシリーズの決まった品を読む。
2. 3 案を並べて作り（形の違い、または飾り・板の絵の置き場所の違い）、1.0・1.1・1.6・1.10 と 2 章に照らしたおすすめを一行添えて、ユーザーに選んでもらう（2026-11-19 からは案の段階で見せて選んでもらっている）。
3. 選んだ案を清書し（手直しを言われた所も入れる）、両面・斜めから確かめ、ゲームに入れて撮る。ラフをそのまま入れない。
4. 清書はゲーム内の撮影（三人称の斜め）を付けて見せる。シリーズや階級でまとまったら、同じ撮り方で並べた画像も作る。
5. 「変」「気になる」と言われたら、どこかを聞いてから直す。推測で一つだけ直さない。

### 1.4 見た目の禁止

- 色違い・同じ骨組みの使い回し（一品一案。51 の 1 章）
- 段々のノイズ（1 単位より細かい段・乱れた段で角を丸めること。1 単位の方眼にそろえて意図して置いたドット絵の輪郭の段は、1.8 の作法として認める）、全部の面の縁に同じ明るい線、大きな光の暈
- 傾けた箱が継ぎ目から外へ出ること（継ぎ目は輪・玉・台で隠す）。継ぎ目を埋めるための球も禁止
- 中が見える模型（閉じた形にする）
- 白い小さな箱一つ（実・粒）。小さく白いものは「何かのゴミ」に見える
- 単色の面（1.7。どの面にもテクスチャを入れる）
- 大きな面を光らせること、細い光る溝（刃の窓に見える）

### 1.5 大きさの目安

2 倍の細かさでは、下の数をすべて 2 倍にして読む（例: 剣の先まで 52〜60 単位、鎚の頭の幅 20 まで）。ゲームの中の大きさは同じ。

| 種類 | 長さ（握りから先、単位） | 幅の上限 |
| --- | --- | --- |
| 剣・鉾 | 先まで 26〜30、柄頭まで −9 | 鍔 14 |
| 大剣・槍 | 先まで 30〜36 | 鍔 16 |
| 鎚・斧 | 頭の中心 15〜18、石突き −9 | 頭 10 |
| 杖・鈴杖 | 先まで 22〜25、石突き −15 | 14 |
| 弓 | 上下の端 ±14〜16 | 前後 8 |
| 短剣・牙・爪 | 先まで 14〜18 | 8 |

### 1.6 階級の見た目（レア度ほど派手。2026-11-19）

- ユーザー「レア度上がれば上がるほど、見た目を派手になるようにしよう。すぐにレア度高いんだなとわかるくらいに」。名前の色を見なくても、模型だけで階級がわかること。
- 派手さは主に**形と飾り**（輪郭の大きさ・二つ目の形・縁取り・対比の金属・宝石・重ねた部品）で出す。光の数は派手さと同じではない。光はどの階級でも任意で、数の上限もない。置く所は品のモチーフから決め、品ごとに変える（弓の握り・刃の中心の線を毎回の型にしない）。
- 参照（1.8）が決めるのは作りの水準。豪華さは階級で決める。

| 階級（ゲーム内の表記） | 見た目 |
| --- | --- |
| コモン（始めの武器） | 素朴な道具。木が基調で、金属は留め具と働く所だけ。光なし |
| アンコモン | 骨格と素材だけ。光はたいていなし |
| レア | 飾りを 1 か所足す |
| エピック | 飾り 2〜3 か所＋弦（弓）などの二つ目の見せ所 |
| ヒロイック | 輪郭が変わる大物の飾り |
| ★ 伝説・神器 | ヒロイック以上。弦や裏側まで凝る。参照 `docs/review/refs_1119/` 以上の派手さ（太い節の弓腕・大きな先の飾り・浮く欠片・金と赤や青緑の強い対比・翼・リボン） |

- 盛りすぎない: 力を入れる所を 1〜2 か所に決め、間は空ける。飾り以外（弓腕の輪郭・細り・反り、素材の対比、象嵌の線、色の流れ）でも豪華に見せる。
- 飾る場所を品ごとに変える（弓なら弦そのもの・弦の側・握りの両側・奥行きの鰭・上下で違う形・浮く衛星・下がる飾り）。同じ場所ばかり飾ると一揃いが同じに見える。
- 弓は弦より後ろへ伸びる飾りもよい（先が弦の後ろへ巻く、弦の後ろに下がる房）。ただし引きの通り道（弦の後ろの y 8〜22）は空ける。
- まっすぐの棒を放射に並べた飾り（扇・光線）は使わない。重ねた板で塊の輪郭を作る。下がる飾りは品の色と長さに合わせ、自然に付ける。
- 巨神・深淵・神器の品は、巨神の素材の言葉（16 の 2.4）を一点繰り返す。

### 1.7 装飾の細かさ（全品でそろえる）

- 基準は決まった品（祠の杖・祠の剣）。迷ったら、この 2 本と同じ角度で並べて比べ、細かさがそろって見えるか確かめる。
- テクスチャは 1 画素 = 1 単位（例外は小さな宝石だけ: 宝石は縁と光の点のある宝石の絵を丸ごと貼る。1 画素 = 1 単位にすると 1〜2 画素の単色になるため）。模様の線は 1 画素以上、模様の中の形は 3 画素以上。1 単位より細かい描き込みはしない。
- 箱は 1 単位以上（輪・縁・板の厚さだけ 0.5 まで）。鋲（小さな粒の箱）は使わない。
- 飾りの量と光は階級で決める（1.6）。
- 格子・ひび・紋などの模様は 1 面に 1 つまで、線は 3 本まで。面いっぱいの細かい網や格子は描かない。
- 部品の数は階級で増える（コモンで 15〜30 個。★ 伝説・神器は 100 前後まで。それより多いと盛りすぎに見える）。
- **単色の面は作らない。** どの面にも何かしらのテクスチャを入れる（陰影の縁・木目・地の色むら・模様のどれか）。宝石も縁の濃い色と光の点を描く。一つの面だけ単色だと、そこだけ急に違和感が出る（2026-11-17、祠の弓の緑青と星石が「のっぺり」）。
- 例（2026-11-17 の祠の鎚 v4）: 正面一面の細いひびの網・細い格子・四隅の鋲・重ねた板で、杖と剣より細かくなりすぎた。

### 1.8 目指す水準（2026-11-18 の参照から）

- 参照は今の模型の約 2 倍細かい画素で作られている（水晶の斧の柄は幅 4 画素）。そのため 2026-11-18 に全品を 2 倍の細かさ（1 画素 = 1/32 ブロック）にした（1.2）。1/16 ブロックの細かさでは、参照の台座・輪郭の飾り・帯の巻きを描く余地がない（鎚の試作で確かめた）。

参照: `docs/review/refs_1118/`（炎の杖・水晶の斧・弓・杖・水晶の蜘蛛・杖を作るタイムラプス）。ユーザーの目標は「全部このレベル」。

| 項目 | 参照がしていること | 決まり |
| --- | --- | --- |
| 塗り | 部品ごとに 3〜5 色の段階で塗り分ける（柄が紫→青へ移る、金が明→暗）。縁に濃い 1 画素、角に明るい点が数個 | 面は単色の地＋1 本の明るい縁ではなく、素材の色の段階で塗り分ける。暗い所の隣に明るい差し色を置いてコントラストを出す |
| 飾り | 飾り（光線の輪・三日月の爪・巻いた腕）は、1 単位の箱を方眼に並べたドット絵の輪郭を、厚み 1〜2 で立体にしたもの | 細かさは輪郭（影）で出す。面の上に細い格子や網を描き込まない（1.7）。方眼にそろった段はよい |
| 見せ所 | 頭と柄の継ぎ目に、面取りした宝石の台座。宝石は濃い縁・中・明るい芯の段階と光る芯 | 品ごとに、継ぎ目の台座と宝石を一つ作る（光るのは宝石の芯） |
| 柄 | 濃い帯と明るい帯が 1〜2 画素ずつ交互に並ぶ巻き | 柄は帯のリズムで塗る（赤い紐でも帯の明暗を付ける） |
| 作り方 | 色を塗った設定画を背景に置き、単色の箱で形を組み、最後に塗る | 担当は先に正面の設定画（色付きの PNG、模型と同じ大きさの方眼）を描いてから組む。設定画をそのまま押し出して模型にはしない（2026-11-17 に却下） |
| 確認 | — | 担当の報告には、作った品を参照と同じ大きさで並べた画像を必ず付ける |

- 参照と比べて足りなかったもの（2026-11-18 の祠の鎚）: ①丸い物（丸太・柄・輪）は角を落とす（大小 2 つの箱を十字に重ねて断面を八角にする） ②丸い物の面は片側を明るく、反対側を暗く塗る（縁の 1 画素だけでは丸く見えない） ③色の段階は色相をずらす（影は赤紫へ、光は黄へ。同じ色相のまま暗くすると泥のように見える） ④小さな石も光の点を 1 つ入れる（3×3 画素以上）。塗りの決まりは `tools/gen/pixel/paint_cubes.py` にまとめた。

### 1.9 作り方の流れ: look5（2026-11-18 夜から。ユーザー「めちゃいい。これで行こう」）

手本は鯨の鎚 v5（`tools/models/x32/look5/whale_hammer.py`、`tools/models/x32/whale_hammer.bbmodel`、`docs/review/whale_hammer_v5_ingame.png`）。古い作り方（設定画 → 箱に貼る絵の板、`concept_boxes.py`、`*_parts.py` と `paint_cubes.py`）は却下された。戻らない。

**見た目の決まり**（「のっぺり」「チープ」「最低でも 2 ドット」「弓みたいに綺麗に曲げる」を直した結果）:

1. 形: 細く長く、全体は一方向に流れる。部品はどれも 2 ドット以上（1 ドットの部品は作らない）。頭は板の塊でなく、1〜2 単位の棒と抜けた空き（枠・鉤・巻き）で組む。
2. 曲線: 段の箱で作らない。少しずつ回した節（`seg` / `chain` / `arc`）をつなぐ。
3. 色: 1 色相の系統に、差し色 1 つと光 1 系統。素材を 5 つ同じ強さで並べない。色は長さ方向に流す（根元が暗く先が明るい）。
4. 面の塗り: 面の向きで明暗（上 +1・横 -1・下 -2）。上と左の縁は明るく、下と右の縁は暗く、左上の角に光。大きな面には 1 画素内側に縁取りの線。点の模様（まだら）は使わない。
5. 元の品の特徴（素材・特徴の部品）は残す。参照の構造は写さない。
6. シリーズごとに形を作り直す（「形自体はシリーズごとに毎回作り直してね」）。握り・柄頭・弓の体・鈴は各シリーズの設計ファイルでモチーフから決める。ほかのシリーズの関数や点の列を借りない（共有するのは `lib.py` の塗りの規則だけ）。同じ種類をシリーズ間で影だけにして比べ、同じに見えたら作り直す。
7. 閉じた形（中が見えない）。継ぎ目を埋める玉は足さない。部品は親に沈めてつなぐ。

**道具**（`tools/models/x32/look5/`）: `lib.py`（塗りの規則・節・円弧・板の絵・弦）、`<シリーズ>_bold.py`（シリーズの設計。品ごとに関数 1 つ）、`preview.py`（下見）、`mstep.sh`（Blockbench への受け渡しと取り込み）、`brush.py`（筆の位置）、`series_check.sh`（持ち方・台帳・撮影・一覧）。

**1 品の流れ**:

1. 設計ファイルに関数を書く（形・素材・下塗り）。案を出すときは 3 案（1.3）。
2. 下見: スクラッチパッドの `pv.sh <名前> <id...>` か `python -I tools/models/x32/look5/preview.py <作業先> <出力.png> <id...>`（表と裏の斜め）。下見は取り込み済みの模型を上書きするので、終わったら `git checkout` で戻す。
3. `bash tools/models/x32/look5/mstep.sh prep <設計モジュール> <id>`（作業フォルダで。`PYTHONIOENCODING=utf-8`）。geo.json・絵・筆の座標（`brush_<id>.txt`）が出る。
4. Blockbench（この順。モードで使える道具が変わる）: `set_mode edit` → `create_project`（free）→ `from_geo_json`（`work/geo/<id>.geo.json`）→ `create_texture`（`work/geo/<id>_tex.png`）→ `list_outline`（箱を含めない）で g_root の uuid → **edit のまま** `apply_texture`（g_root の uuid、applyTo all。paint にしてからだと面に付かない）→ `set_mode paint` → `paint_with_brush` を 3 回（brush の 3 色と座標、connect_strokes false）→ `export_model`（codec project、`work/out_<id>.bbmodel`、overwrite）。
5. `bash tools/models/x32/look5/mstep.sh done <id>`（絵の付いていない面があると止まる）。
6. ゲームで撮る: `bash tools/models/x32/look5/series_check.sh <名前> <id...>` → `docs/review/<名前>_ingame.png` と `_bb_sheet.png`。ゲーム内の斜め（三人称）で判断する。正面の下見だけで決めない。
7. ブラッシュアップを 3 回以上: 表と裏の斜めを大きく撮って参照（`docs/review/refs_1118/`・`refs_1119/`）と比べ、足りない所を 3 つ書き出して直す（設計ファイルを直して 3〜6 をやり直す）。見る所: 輪郭（角を落とす・段で細く・張り出し）、層の深さ（2〜3 段）、見せ所の台、部品ごとの色の段階と境の暗い線と角の明るい点、表と裏の描き込み。大きな差がなくなるまで続けてから次の品へ。

**正直に書く**: スクリプトで置いた箱は「手で作った」と言わない。報告では、設計ファイル（スクリプト）で作った所と、Blockbench で目で直した・筆で描いた所を分けて書く。

**進め方**: シリーズごとにコミット（m1-sky-pass。main には入れない）。ラフはそのまま入れない（選んだら清書してから入れる）。使わなくなったラフの設計ファイルと取り込み物は消す。

### 1.10 形そのものをデザインする・板の絵（2026-11-19）

- **基の形から線を出すだけにしない**（ユーザー「弓の元の形から線出すだけみたいな形やめてほしい。弓の元の形自体をデザインすればいいのでは」）。弓腕・刃・頭の輪郭そのもの（幅の変化・輪郭・切り欠き・節）をモチーフにする。例: 弓腕が二頭の鯨、弓腕が鰭、弓腕が炎、弓腕が角笛・望遠筒・翼・坑道の鉄枠。飾りはそのあとに控えめに。
- **板の絵**（厚みのない絵の板。`lib.Model.decal` / `picture` / `Canvas`。xy の板と、横向きの zy の板）: 3D の中に 2D のドット絵を入れてよい。ただし**本当に平たいもの**だけに使う（翼の羽・鰭の膜・炎・稲妻・風の筋・印の輪・照準）。網・柔らかい霞・音の波は合わなかった。音や光の広がりは 3D の部品（例: 横に寝た光の輪）で作る。
- 板の絵は `Canvas.put` が必ず `finish()` を通す（孤立した点を消す・上下の縁に明暗・外に 1 マスの濃い縁取り）。1 マスの細い線や散った点で描かない（ちらつく点に見える）。
- 置き場所: 模型の中に埋もれる所（太い部品の中の z=0）や、正面からしか見えない所に置かない。形の外へはみ出して輪郭を作る所（翼の先の扇、弓の先、握りの前）に置き、三人称の斜めで見えるか確かめる。横向きの板は横からは見えない。
- 先に試して決める: 板の絵を入れる品は 3 案（置き場所の違い）を並べて選んでもらう。

### 2.3 魔法使いの担当（星読み）— 杖

| 項目 | 中身 |
