# 15 全モデルのハイポリゴン化 — 設計と試作

ベータ版 (巨神 4 体) のあと、全モデルを「箱を並べただけ」から「彫ったもの」へ作り直す。
この章は、その設計 (細かさ・描画の予算・手順・担当分け) と、代表 3 体の試作の結果。
決まり: 3D は 2D を厚くしただけに見せない / 重なって埋まった箱は禁止 (`check_overlaps`) / 32px 密度のテクスチャ / 武器は mob に焼き込まず別モデルで手のソケットへ。

- 箱の数に大きな差がある。巨神近景・番兵長・心臓・雷獣は 700〜2600 箱でもう細かい。番兵・語り部・イサナ・見る者・水路の顎・射手・磯走りは 50〜90 箱で、いちばん「箱」に見える。

## 2. 方針

### 2.1 着想: 箱を切り分ける (hpkit)

作り直しの中心は `tools/rough/hpkit.py`。出来上がった geo とテクスチャを読み、箱を**互いに重ならない小箱に切り分け**て、角を階段状に丸める・穴を掘る・細部の箱を足す。

- 切った小箱の面は、元の箱の同じ向きの面の同じ位置のテクスチャを使う。**テクスチャは変えない** (新しい絵は要らない)。
- 切り口で新しく見える面 (段の壁) も、元の面の同じ座標を使う。中に埋まった面は出さない (面数が節約になる)。
- 小箱は重ならないので `check_overlaps` はきれいなまま。ボーン・pivot・回転は触らないので、アニメは変わらない。
- 試験 (`tools/rough/hp_selftest.py`): 切るだけで何も削らない場合、描画が元と同じ (違う画素は 0.1% 未満)。

### 2.2 細かさの使い分け

| 単位 | 使う所 | 理由 |
|---|---|---|
| 0.5 (= 1 画素、32px 密度) | 大きな部品の面取り、顔・手・縁・装飾の主な形 | テクスチャの 1 画素にちょうど合う。段が見える最小の細かさ |
| 0.25 | 顔・手・縁・飾りだけ (見える所だけ)。面取り 0.25、リベット、指、歯、牙 | 面が半画素になるので、単色の飾りにだけ使う (下の 2.4)。大きな面には使わない |
| 1.0 以上 | 体の大きな塊、巨神の中・遠景 | 細かさが見えない所は粗いまま |

目安: 見える所 (正面から見て 1 画素が 1 度以上に見える所) だけ 0.25。背中側や下側の小さな所、普通の距離で見えない所は 0.5 のまま。

### 2.3 面取りと起伏の作り方

| 手法 | `hpkit` の呼び方 | 向く所 | 面数の増え方 |
|---|---|---|---|
| 一段の面取り | `round_all(step=0.5, R=1)` | 大きな箱 (短い辺が 2 以上) | 箱が 3〜5 倍、面は 2.5 倍前後 |
| 二段・三段の丸め | `R=2`、`R=3` | 頭蓋・胴・胸甲など大きな塊だけ | 箱が 5〜9 倍 |
| 一辺だけ丸める | `axes="xz"` など | 腕・脚 (八角柱) | 3 箱 |
| 穴を掘る | `round_cube(holes=[...])` | 眼窩・鼻・口・彫り込み | 穴の面だけ増える |
| 細部の箱を足す | `add_box` (`safe=True` で重なりを避ける) | 眉・頬骨・リベット・縁の枠・指・歯・膝 | 1 箱ずつ |
| 浮き彫りの筋 | `ridges` | 殻の筋・毛並み・装甲の継ぎ目 | 筋の数だけ |
| 光る点を足す | `add_box(glow=True)` | 目・結晶 | glowmask に画素が増える (光る画素ゼロでは落ちるので注意) |

### 2.4 テクスチャの密度との釣り合い

- 32px 密度 = 1 単位に 2 画素。0.5 の箱の面は 1 画素角、**0.25 の箱の面は半画素**で、普通に UV を書くと隣の画素を拾う (光る画素も拾ってしまう)。
- 対策 (hpkit に実装済み): 1 画素より小さな面は、面の中心の画素 1 つだけを拾う (UV を画素の中心に寄せて 0.5x0.5 にする)。足す飾りは「1 色 = 2x2 画素の見本」をテクスチャの下に追加して拾う。
- だから 0.25 の箱は**単色の飾り**に限る。柄のある面は 0.5 以上にする。
- 密度を 64px にして細かく描く案は、今回は取らない (ユーザーの決まりは 32px。絵の描き直しが全モデルに及ぶ)。顔・手だけ 64px にする案は 15.9 の判断に入れる。
- 切り分けでテクスチャの大きさは変わらない。飾りの見本で下に 2〜数行増えるだけ (番兵: 66 → 82 行)。

## 3. 描画の負荷の予算

### 3.1 実測 (`ShotRunner` の `perf` 手順、`tools/shots/hp_sentinel.txt`)

骨の番兵 36 体を NoAI で並べて 300 tick のフレーム時間を測った (この PC、描画 8 チャンク、垂直同期なし、1280x720)。

| 状態 | 箱 / 面 (1 体) | フレーム時間 | 1 体あたりの増分 |
|---|---|---|---|
| 今 (発光層なし) | 56 / 336 | 3.4〜4.1 ms | 基準 |
| C 案・発光層なし | 236 / 1243 | 7.7 ms | +0.12 ms (面が +907) |
| C 案・発光層あり (目が光る) | 同上 | 13〜18 ms | +0.27〜0.4 ms |

読み取り:
- GeckoLib の描画は CPU で面ごとに頂点を作るので、**面数にほぼ比例**し、1 面あたり約 0.13 µs (この PC)。箱の数でなく面の数で予算を立てる。
- **発光層 (AutoGlowingGeoLayer) はモデルをもう一度描く**ので、面の費用が 2 倍以上になる。光る所のあるモデルは面の予算を半分で見る。
- ばらつきが大きい (13〜18 ms)。比べるときは同じ台本を 2 回回す。

### 3.3 負荷を抑える作り方

| 手 | 内容 |
|---|---|
| 見える面だけ出す | hpkit は埋まった面を出さない。元の geo にも不要な面があるので `hp_geo_stats.py` の面数で洗う |
| 小さな箱は面を減らす | 0.25 の飾りで見えない向きの面は uv を書かない (`add_box(faces=...)`) |
| LOD で捨てる | 巨神は中・遠で元の粗い箱を使う (今のまま)。敵・中ボスにも LOD は付けない (距離で見えなくなるため、まず予算を守る) |
| 発光は点で足す | 面積の広い glowmask は避け、目・結晶・筋だけを光らせる |
| 発光層の要否を決める | 光る所の無いモデルは `glow=false` (`GuardRenderers.geo`) |

## 4. アニメへの影響 (骨の割り方)

| 事柄 | 方針 |
|---|---|
| 骨の木・pivot | 変えない。hpkit は箱だけを差し替える (アニメ・ソケット・molang は動く) |
| 骨の細分化 | 指・歯・顎・耳など、**動かしたい細部だけ**新しい骨を足す (番兵の指は今は手の骨に付けている。指を曲げるなら子骨に分ける)。骨が増えると 1 体あたりの計算も増えるので、敵は 1.5 割増まで |
| 丸めた箱の回転 | 箱ごとの回転 (`rotation`) を持つ箱は丸めても回転を引き継ぐ。ただし `check_overlaps` は回転した箱を厳密に比べないので、目で確認する |
| 動く部品の隙間 | 関節の近くを丸めると隙間が見える。関節 (pivot の上下 1 単位) は面取りしない (`rule` で外す) |
| 武器 | 手のソケットに別モデルで付ける。mob に焼き込まない (今まで通り) |

## 5. 生成スクリプトで作り直す手順

1. 元の geo とテクスチャを `tools/sources/hp_base/<種類>/` に控える (番兵で実施済み。やり直しはここから)。
2. `tools/rough/hp_<モデル>.py` (番兵は `hp_sentinel.py` が見本) で: `hpkit.Model.load(名前)` → `round_all(rule=...)` → 穴 (`round_cube(holes=)`) → `add_box` の飾り → `hpkit.stats` と `hpkit.overlaps` で箱・面・重なりを確認。
3. `voxel` 描画で「今 / A / B / C」を並べたシートを `docs/review/high_poly_roughs/` に出し、review ページで選ぶ (新しい見た目はまずラフ、の決まり)。
4. 採用案を `m.save(...)` で geo・テクスチャ・glowmask に書き出し、`assets/skyabyss/geo/...` と `textures/...` に入れる (取り込みスクリプトは各家族の `install_*.py` に「hpkit の処理」を足す形にする。焼き済みの心臓は geo を直接差し替える)。
5. 光る画素を足したら glowmask を置き、レンダラーの発光層を有効にする (`GuardRenderers.geo(..., glow=true)`)。光る画素ゼロの glowmask は落ちる。
6. `./gradlew compileJava --offline`、`SKYABYSS_SELFTEST=1 ./gradlew runServer`、`runShots` で前後を撮る。

## 7. 試作の結果 (前後の比較)

代表 3 つ。それぞれ「A 一段面取りのみ (自動)」「B 大きな箱は二段丸め + 小さな箱は 0.25 面取り」「C B + 手の細部 (番兵) か浮き彫りの筋 (心臓・雷獣)」を作り、`docs/review/high_poly_roughs/` に並べた。重なりはすべて 0。

| モデル | 今 | A | B | C | 推奨 |
|---|---|---|---|---|---|
| 骨の番兵 (`bone_sentinel.png`) | 56 箱 / 336 面 | 168 / 896 | 202 / 1068 | **236 / 1243** (眼窩を掘って目が光る、頬骨・眉・縁の枠・リベット・指・肋・膝) | **C** (ゲームに取り込み済み) |
| 潮殻の心臓 段階 1 (`tide_heart_p1.png`) | 669 / 2202 | 899 / 3375 | 701 / 2357 | 728 / 2519 | **作り直し (後述)**。面取りだけでは差が出ない |
| 雷獣 (`raiju.png`) | 924 / 4027 | 1946 / 9629 | 1772 / 8473 | 1821 / 8767 | B (8,400 面で中ボス上限。範囲を絞って 6,000 面台を狙う) |

見えたこと:
- 箱が少ないモデル (番兵) は、丸め + 穴 + 細部の組み合わせで見た目が大きく変わる。丸めだけ (A、B) は小さく見ると差が少ない。**穴と光る目と指が効く**。
- すでに 0.5 の小箱で組んだモデル (心臓・雷獣) は、面取りで面数が 1.1〜2.4 倍になるのに見た目はあまり変わらない。この種のモデルは、面取りでなく**元の彫りを 0.25 の細かさで作り直す** (ring や尾を階段 0.25 にする) ほうが効く。その場合の面数は 4 倍近くになるので、予算 (3.2) に収まる部位だけ。
- 自動の処理は、箱の少ないモデルの底上げと、大きな面のある部品 (胴・頭・甲羅) に向く。

## 中ボスの記録 (担当 2: 番兵長・潮招き・雷獣・鍛え手)

作り方は 1 本のスクリプト `tools/rough/hp_midboss.py` (4 体の A/B/C、`--install <名前> <案>` で取り込み)。元の geo・テクスチャ・発光マスクは `tools/sources/hp_base/entity/` に控えてあり、ラフは必ずそこから始める (取り込み後に走らせても二重に丸めない)。比較画像は `docs/review/high_poly_roughs/{whalebone_captain,tide_beckoner,raiju,ash_smith}.png` (今 / A / B / C を 4 視点で並べた)、ポーズ確認は `*_pose.png`、ゲーム内の前後は `ingame/midboss_{captain,beckoner,raiju,smith}.png` と `midboss_all_four_{before,after}.png`。案は 3 つで共通: **A** 自動の面取りだけ、**B** 大きな塊の丸め + 0.25 の飾り、**C** B + 手で足す細部。採らなかった A・B は `docs/review/high_poly_roughs/assets/<名前>_{A,B}/` に残し (雷獣の A・B は試作のものを今回の絞った範囲で置き換えた)、採った C は取り込み済みなので置かない。重なりは全案 0、光る画素は元のまま (番兵長 172、潮招き 1,748、雷獣 1,464、鍛え手 18,700)。

推奨はどれも C (B との差は 40〜600 面で、細部の分だけ)。A は 2 体で上限を超える。最小の箱は 0.25。

| モデル | B の中身 (丸め + 0.25 の飾り) | C で足したもの |
|---|---|---|
| 番兵長 | 兜・拳・腿の大きな箱を二段丸め。腕・脚の骨は縦の辺だけ (`axes="xz"`、関節の面は残す)。背骨 8 本は触らない。飾り: 目のあいだの鼻梁、覗き窓の縁、兜の冠の継ぎ目、拳の関節の出っ張り、前腕の腕当て | 指 4 本 + 親指、兜の口の格子 (暗い 6 枚) |
| 潮招き | 甲羅の段 (厚さ 3、幅 40〜60) と爪の塊を 1.0 刻みで二段丸め、細い部品は 0.25。飾り: 目の枠、脚の関節の棘 (全 6 脚) | 大鋏の歯 (上下の顎に 2 段の歯 × 12)、爪の筋 (0.25 の高さ)、甲羅の背棘 |

| 鍛え手 | 頭・腕・前腕・脚・腹と、胴の積み板を丸める (大きな板は二段)。鞴 2 つ (約 220 箱) と前掛けは元のまま。飾り: 兜の覗き窓の上下の縁、口の格子 5 枚 | 胴・脚の板の鋲 (約 85) |

見えたこと:
- **番兵長・鍛え手は元から 0.5 の階段で彫ってあり、テクスチャも描き込み済みなので、丸め + 0.25 では「少し滑らかになり、顔と手に付け足しが入る」程度**。ゲーム内でも差は顔・手の接写で分かるが、全身では小さい。番兵 (箱が 56 個) のような大化けは無い。大きく変えるなら、鍛え手の炉の口・兜、番兵長の兜を 0.25 で彫り直す (別の手間)。
- **潮招きは差が大きい**: 箱 188 の粗いモデルで、丸め (1.0 刻み) だけで殻と爪の見え方が変わる。鋏の歯が付いて、大鋏が「鋏」に見える。
- 雷獣は B の範囲を絞って 6,000 面台に収まった。顔の牙・眉は近くで分かる。
- 面取りの後に足す箱は、同じ場所に元の箱があって入れないことが多い (`safe=True` が黙って捨てる)。スクリプトは捨てた箱を `SKIPPED` に覚えて表示する。座標を直すときは `python tools/rough/hp_midboss_probe.py <名前> x0 y0 z0 x1 y1 z1` で、その範囲にある元の箱を引く。

### アニメ・色・発光

- 骨の木・pivot は変えていない (箱だけの差し替え)。`hp_midboss_pose.py` で腕・脚・顎・尾・爪を曲げた姿勢を 4 体とも今と並べて確認した (`*_pose.png`)。隙間・めり込みは見えない。潮招きの爪の付け根 (肩の近く) は 1.0 刻みの丸めで角が落ちるが、胴の殻に隠れる。
- 鍛え手は白い発光マスク (`ash_smith_glowmask_white.png`、鞴が白く光る間と怒りで重ねる) もテクスチャと同じ uv なので、取り込みで作り直した (`install_ember_smith.py` の `whiten` と同じ式)。geo は元の整形 (indent=1) のまま書く (`AshSmithSelfTest` が `"name": "bone"` の文字列を探すため)。
- 暗い飾りの色は、元のテクスチャに掛けた持ち上げ (08 の 19.8 節) と同じ式を通す (`shade()`)。部屋の明かりで沈まない。
- `install_{tide_caller,raiju,ember_smith}.py`・`gen_mobs.py` は元の geo を作り直して上書きするので、取り込み後に走らせない (走らせたら `hp_midboss.py --install <名前> C` で戻す)。

### ゲーム内の測定 (`tools/shots/hp_midboss.txt`、`hp_midboss_perf.txt`)

NoAI の中ボスを平らな玄武岩に置き、同じ台本を取り込み前後で回した (描画 8 チャンク、1280x720)。

| 状態 | 番兵長 ×6 | 潮招き ×4 | 雷獣 ×6 | 鍛え手 ×6 | 4 種 ×2 (計 8) |
|---|---|---|---|---|---|
| 今 | 14.4 ms | 3.4 ms | 11.7 ms | 10.7 ms | 9.5 / 10.2 / 11.0 ms |
| C | 19.6 ms | 17.8 ms | 19.0 ms | 18.9 ms | 29.7 / 30.2 / 19.4 ms |
| 1 体あたりの増分 | +0.9 ms | +3.6 ms | +1.2 ms | +1.4 ms | |

- 面の増分あたり 0.5〜0.9 µs。**3.1 の「1 面 0.13 µs」(発光 2 倍で 0.26) の 2〜3 倍**。この台本は NoAI のボスを多数置くので、ほかの worktree のゲームが同時に動いていた回もあり (8 体の測定が 19〜30 ms とばらついた)、値は目安。ただ傾向として、中ボスの上限 8,000 面は **1 体あたり 4〜5 ms** と見るのが安全。実戦は 1〜2 体なので許容と判断したが、判断 9-1 (予算の見積もり) で効く。
- 重いと感じたら、潮招きを B (6,256 面) に戻す、鍛え手の胴の二段丸めを一段にする、で 1 割ほど減る。
