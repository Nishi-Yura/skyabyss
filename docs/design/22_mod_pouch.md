## 1. ねらい

バニラの持ち物は、剣や食べ物や建材と、mod の鍵・心核・欠片・鱗片・笛が混ざってかさばる。しかも、巨神編が進むほど「落としたくない品」が増える。そこで次のようにする。

1. **バニラの持ち物 = バニラの品と武器・防具・装飾・食べ物。旅嚢 = この Mod の集める品・鍵・笛。** 分けて遊べるようにする。
2. 袋の品は**拾えば勝手に袋へ入る**。持ち物の枠を取らない。
3. 袋の品は**倒れても失わない**。墓にも入らない（11 の 6 章と矛盾しない。5 章）。
4. 使う品（笛など）は、持ち物から探さず、キー一つで使える（10 章）。
5. 袋は**品の種類ごとに決まった枠**を持つ。その枠にしか置けず、並びは変わらない。集める楽しみ（空の輪郭を埋める）も出す。

名前は「旅嚢」（たびのう。英語は Travel Satchel、つまみは Satchel）。主人公は「留まる者」（ループでも留まる）で、袋は「ループを越えて手もとに留まる品」を入れる。画面の文では「袋」と略してよい。

## 2. 入れる品・入れない品

品の登録を調べた結果（`ModItems`・各巨神の `*Setup`）。決め方の基準は「**集める・渡される・守るべき品で、手に持って戦わないもの**」。

### 2.1 袋に入れる（30 種ほど）

| 区分 | 品 | 上限 | 理由 |
| --- | --- | --- | --- |
| **使う道具** | 呼び笛・呼び貝（巨神ごと。岩鯨の呼び笛・潮殻の呼び貝・雷翼と余燼は同じ型で増える）、潮見の貝、風見鶏 | 1 | 右クリックで使う旅の品。守る品（11 の 4.1）でもある。キーで使えると持ち物の枠を空けられる |
| **鍵と心核** | 天の鍵の欠片、天の鍵、火の鍵（焼き入れ後）、巨神ごとの心核（岩鯨・潮殻・雷翼・余燼） | 欠片 4／鍵 1／心核 99 | なくすと困る品の筆頭（11 の 4）。扉・仕掛けは袋にあれば持っていなくても通す（8.3） |
| **共鳴** | 共鳴の結晶、共鳴の欠片（岩鯨・潮殻・雷翼・余燼。古い欠片は「古い」の 1 枠） | 999 | 共鳴の炉の費用と通貨。かさばる数が増える品で、倒れて失うと痛い |
| **書** | 伝承の書、破れた頁 | 1／99 | 書は「なくしても戻る」（05）が、袋に入れば戻る手間も要らない |
| **巨神の素材** | 岩鯨の鱗片、潮殻の殻片、雷翼の羽軸、余燼の燠石 | 999 | 強化・鍛えに使う集める素材。数が多くなる代表 |
| **小さな素材** | 鱗粉、泡袋、火の粉の粉、燠の殻、潮干しの貝、潮の真珠 | 999 | 巨神の敵が落とす細かい素材。バニラの持ち物を圧迫する側の品 |

- 巨神が増えたとき（五章以降）は、区分の行に枠を足す。品の一覧は `PouchEntries`（登録の表）で一か所に持ち、巨神の登録（`Titans`・`TitanKind`・`TitanPages`）から自動で足せるようにする（心核と呼び笛は今も `Keepsakes.guardedItems()` が同じ作りで一覧を組んでいる）。
- 上限は袋の中だけの数え方。バニラのスタック上限（64・99）に縛られない（保存は 8.1 の独自の形）。

### 2.2 袋に入れない（バニラの持ち物のまま）

| 品 | 理由 |
| --- | --- |
| 武器・防具・盾・弓・矢（骨棘の矢）・大剣などの専用装備 | 手に持つ・身につける品。袋に入れると戦えない。ホットバーと枠の並びが大事 |
| 護符・装飾（共鳴の護符、巨神ごとの護符・足環・羽根・外套・灯・護石・補強板・真珠） | すでに専用の装飾の枠（`skyabyss:accessories`）がある。二重の専用枠にしない（枠は 3 つ。03 の 6 章） |
| 食べ物（雲上の干し肉、雲間の干し果、熾火の角杯）、温石 | 食べる・使い切る消耗品。持ち物の枠に置いて手で食べるのが自然 |
| 背中の試練の道具（灰の壺、熾、火の鍵（焼き入れ前）、鍛え手の大鎚、灰被りの火掻き） | 手に持って運ぶこと自体が試練（熱で落とす・ブロックへ置く・鍛える）。袋に入れると試練が成り立たない |
| スポーンエッグ、バニラの品、ブロックのアイテム（共鳴の炉・碑・燠の灯など） | 建てる品。クリエイティブの品も袋へは送らない（4.4） |

境目が揺れる品は、実装前に使い方を確かめて区分を移す（風見鶏・潮見の貝・天の鍵が「手に持たないと使えない」なら 2.2 へ戻す。確かめる担当は 12 章の P1）。

### 2.3 素材を袋に入れる理由

素材（鱗片など）は「なくすと取り戻せない」わけではないが、(1) 数が増えて持ち物を圧迫する最大の原因、(2) 巨神の戦いで死ぬたびに墓へ取りに行かされる苦痛、の二つが、ベータの「全ロスは萎える」「取りに行くのも面倒」の主因だった。袋は「修理や強化の素材は気にせず溜められる」場所にもなる。上限を 999 にして「溜め込みすぎ」も防がない。

## 3. 枠の考え方

**品の種類ごとに決まった枠（固定枠）**。持ち物のような自由な升目にしない。

| 項目 | 決まり |
| --- | --- |
| 枠の数 | 品の登録の数。1 つの品に 1 つの枠。今の登録で 30 枠ほど（2.1 の表）。九列の升目に区分ごとの名札と一緒に並べる |
| 置ける品 | その枠の品だけ（`mayPlace`）。ほかの品は置けない。手でも置けるが、普通は拾うだけで入る（4 章） |
| 個数 | 枠ごとの上限まで積む。2.1 の「上限」の欄 |
| 並び | 登録の順で固定。品が増えても既存の枠の位置は動かさない（区分の最後に足す）。ずれない |
| 空の枠 | まだ手に入れていない品の枠は、その章まで来たら**輪郭だけ**（その品の暗い影）、その章に着く前は「？」（名前も形も出さない。物語の核心を漏らさない） |
| 一覧の保存 | 枠の位置は保存しない。品の ID と個数だけ保存する（8.1）。枠の並びが後で変わっても、保存を直さなくてよい |

固定枠にする理由（升目＝自由に置けるバッグにしない）:

- 「そこにしか置けない」「専用枠」の要望どおりで、何がどこにあるか迷わない。
- 品を一覧にして**集める楽しみ**（輪郭を埋める）が作れる。
- 保存は ID と数だけで軽く、他の mod の品が混ざらない。移し替えのバグが起こりにくい。
- 升目だと「空きがない」状態があり得て、ここでの「勝手に入る・失わない」の保証が難しくなる。

## 4. 拾うと勝手に袋へ入る

mod は Mixin を使っていない（03 の 6.4）。そこで、入口を次の三つにそろえる。

### 4.1 入口

| 入口 | 仕組み |
| --- | --- |
| 地面の品を拾う | `ItemEntityPickupEvent.Pre`（NeoForge）で、袋の品なら拾う動きを横取りして袋へ入れる。拾った音は小さく鳴らす。持ち物には入らない |
| この Mod の渡し | 報酬の渡し（`TitanLoot.give`）、運び出し・眠りの場面の渡し、クエストの報酬、呼び笛・心核・欠片・天の鍵・火の鍵の「渡す」、墓・救い・預かり（`GraveRescue`・背中の預かり）から返す品、`KeepsakeBonds` が呼び戻す品、`/give`（`PouchRouting.give(player, stack)`）。いまの `player.addItem`・`give` の呼び出しを `PouchRouting.give` に置き換える。袋に入る品だけ袋へ、残りは今までどおり持ち物 → 足もとの順 |
| 取りこぼし（掃除） | 1 秒ごとと、画面（持ち物・箱）を閉じた瞬間に、持ち物とカーソルの品を調べ、袋の品があれば袋へ移す。他の mod の箱・取引・コマンドで入った品、クリエイティブの品を受け止める保険。高くても 1 秒だけ持ち物に見える |

### 4.2 墓・預かりとのつなぎ

袋の品は墓・預かりには**入らない**（5 章）。ただし、すでに墓・預かりに入っている昔の品（8.2 の移し替え前のセーブ）は、取り出した瞬間に 4.1 の掃除で袋へ移る。

### 4.3 知らせ

袋に入ったことは、チャットに出さない（18 の方針）。初めて手に入れた品だけ、右上の札（獲得）に一行「**旅嚢**へ入れた」を添える（以後の同じ品は札を出さず、袋の画面の枠が金に一瞬光るだけ）。袋がいっぱい（上限）の品は、持ち物へそのまま入れて「袋がいっぱい」と一度だけ告げる。

### 4.4 クリエイティブ

クリエイティブの持ち物の画面には袋のつまみを出さない（装飾と同じ既知の制限。03 の 6.5）。袋の品は、キー I（10.1）かコマンドで開く袋の画面で扱う。クリエイティブのカーソルの品は、4.1 の掃除で袋へ入る。袋の品を「作って持つ」ときだけは、持ち物に残したいことがあるので、`/skyabyss pouch hold on` を管理者用に用意する（掃除を止める）。

## 5. 倒れたときと墓

- **袋の中身は、どの型でも（墓・バニラ・全部残る・控え・バニラの `keepInventory`）失わない。** 墓にも入らない、散らばらない、耐久の減りもない（耐久のある品は入れない）。
- 実装: 袋はプレイヤーの Data Attachment（8 章）で、`copyOnDeath()` を付ける。`DeathEvents`の「大事な品を持って復活」の仕組み（`Keepsakes.guarded`）は、袋の品なら対象外にする（すでに袋が持っているので重ねない）。袋の外に残った品（掃除前の 1 秒の品、カーソルの品）は今までどおりの扱い（守る品は持ち物に残る）。
- 背中の死（02 の 7 章）も同じ。預かりは持ち物だけ。袋は触らない。
- 11 の 6 章の表の「大事な品」は、**袋のあるものは袋が守る**と読み替える。墓の自己テストの「大事な品が手もとに残る」は、袋を含めた数えで通す。
- ほかの人に殺される・奈落・溶岩・火で消える、のどれでも袋の中は無関係。
- 控え帳の在りか: 袋の品は「**手もと**」に数える。`Keepsakes.registerHolder("pouch", …)` を起動時に呼び、在りかの行に「旅嚢 ×n」を足す（文 `d.place_pouch`）。`Holder.take` も実装し、天の鍵がそろうとき袋から欠片を取り除ける（11 の 4.3）。
- 取り戻しの二つの仕組み（11 の 4.2。心臓をもう一度倒す・「呼び戻す」）は、前の代の品を砂にする。袋の中の前の代は、新しい代へ書き直す（`KeepsakeBonds` が袋も巡回する）。

## 6. 落とせない・箱に入らない・渡せない

| 操作 | 決まり |
| --- | --- |
| 投げ捨て（Q・画面の外） | できない（袋の品は持ち物にないので、そもそも投げられない）。11 の 4.1 の「守る品は投げ捨てられない」と同じ結果になる |
| 箱・樽・シュルカー・ホッパーへ入れる | できない（持ち物にないので入れる手段がない）。袋の枠からのシフトクリックは、袋の画面の中では何も起きない |
| 他のプレイヤーに渡す | 鍵・心核・笛・欠片（11 の 4.2 の「持ち主に結ぶ」品）は渡せない。素材・共鳴・小さな素材は **取り出し**（枠を右クリック／ボタン）で最大 1 スタックを持ち物へ出せる。出した品は「取り出し済み」の印（データ部品 `skyabyss:pouch_loan`）が付き、掃除が袋へ戻さない。もう一度袋に入れる操作（枠へ置く・拾い直し）で印が外れる |
| ほかの人から受け取る | 取り出し済みの素材は、拾った人の袋へ入る（印は外れる）。つまり素材のやり取りは「取り出して渡す」でできる |
| 取り出し自体 | 設定（ゲームルール `skyabyssPouchWithdraw`、既定 1）で切れる。0 なら素材も出せない |

11 の 4.1 の「人に渡すときは箱を通す」は、鍵・心核・笛では要らなくなる（そもそも渡さないので）。11 を実装するとき、その一行を直す。

## 7. マルチとパーティ

- 袋は**一人ずつ**。パーティで共有しない。理由: 品は一人一つ（11 の 4.2 の持ち主の印と代）で、心核・笛・鍵は個人の進みに結ぶものだから。素材だけは 6 の取り出しで渡せる。
- 背中の進み（10 の 10 章）は今までどおりグループごと。袋と無関係。
- 管理者は `/skyabyss inspect <人> pouch` で他人の袋を見られる（読むだけ。控え帳の「変わった値」と同じ作り）。
- 他人の袋は見えない。サーバー → 持ち主にだけ同期する（8.2）。

## 8. 保存・同期・既存セーブ

### 8.1 保存

- プレイヤーの Data Attachment `skyabyss:pouch`（`PouchData`）。`copyOnDeath()`。コーデックは **品の ID → 個数 と 品の部品（持ち主の印・代など）** の一覧。`ItemStack` の個数の上限が 99 なので、袋の中は独自の `record PouchStack(ItemStack proto, int count)`（proto は個数 1 の見本）で持つ。
- 枠の位置は保存しない（3 章）。登録にない品の ID はそのまま保存して読み飛ばす（mod を抜いたあと戻しても消えない）。
- 版 `v` を 1 から持つ。保存の形を変えるときは版を上げて読み替える。

### 8.2 同期

- 持ち主のクライアントへだけ（`AttachmentType.sync` の `SyncPredicate` で自分だけ）。変わったとき・ログイン・次元をまたぐとき・リスポーンのときに差分を送る。画面を開いていないときは数だけ（HUD の輪・道具帯の絵のため）。
- 画面の中の操作（置く・取り出す）は、メニューのパケットで、サーバーが決める（クライアントは計算しない。11 の 3 章と同じ方針）。

### 8.3 袋を読む側（使う側）

| 使う側 | 変更 |
| --- | --- |
| 共鳴の炉（強化・再鍛造・交換・振り直し） | 費用の結晶・欠片・素材を持ち物でなく袋から払う。炉の画面に袋の数を出す（持ち物にも同じ品があれば足し合わせる。ふつうは無い） |
| 扉・仕掛け（天の鍵・火の鍵を差す所、封印の扉など） | 「手に持つ」でなく袋にあれば開ける。持っていなくても通す |
| クエスト・伝承（条件の「持っている」） | `Condition` の「持つ」は `Keepsakes.have`（袋 → 持ち物 → 箱…）で数える |
| 控え帳（B） | 在りかの「手もと」に袋を足す（5 章） |
| 通知・進捗（19） | 「手に入れた」の判定は拾った瞬間（袋へ入った瞬間）に出す |

### 8.4 既存セーブの移し替え

- ログイン時（`PlayerLoggedInEvent`）と、袋の版が上がったとき、持ち物（メイン・防具・左手）・エンダーチェスト・預かり（`skyabyss_death_keep`・背中の預かり・報酬の預かり）・墓（自分の墓の中身）の**袋の品を袋へ移す**。一回だけ走る（袋に `migrated` を持つ）。
- 箱・樽に入れた分、他人の墓の分は、そのまま（取り出したら 4.1 の掃除で袋へ入る）。
- 移したことは、初回だけ札で「持ち物の mod の品を、旅嚢へ移した」と告げる。移した数は控え帳の履歴に残す。
- 装飾の枠・既存の装飾（`skyabyss:accessories`）は触らない（2.2）。

## 9. 画面

### 9.1 開き方

| 開き方 | 中身 |
| --- | --- |
| 持ち物の画面（E）の上の「**旅嚢**」のつまみ（既定） | 装飾と同じ「持ち物 / 装飾 / 旅嚢」の三つ並び（03 の 6.5）。つまみはレシピ本を開いて画面が右へ寄ってもついていく |
| キー **I**（既定。設定で変えられる。開いている間にもう一度押すと閉じる） | 旅嚢の画面を直接開く（クリエイティブでも開く） |
| `/skyabyss pouch` | 管理者用の確かめ（読み書き） |

### 9.2 画面の置き方（決定: A つまみ。ラフは `docs/review/_gallery_pouch/`、本番の絵は 16 章）

| 案 | 中身 | 良い点 | 悪い点 |
| --- | --- | --- | --- |
| **A つまみ（推奨）** | 装飾の画面と同じ作りの別の画面。区分の名札つきの固定枠。持ち物の下側は出さない（自動で入るので手で入れない） | 装飾と同じ作りで軽い。レシピ本と重ならない（持ち物の画面ではないため）。他の mod の右側のボタンとも重ならない | 持ち物と同時には見られない |
| B 脇のパネル | 持ち物の画面の右に五列のパネルを付ける | 同時に見える | 画面が広がり、JEI などの右側と重なる。名札・説明の置き場がない。枠の番号がずれて他の mod・クリエイティブが崩れやすい（03 の 6.4 と同じ理由） |
| C 別の画面（キー I だけ） | 羊皮紙の広い画面。左に区分、真ん中に枠、右に説明（使い方・旅のようす） | 説明が出せる | 画面が増え、控え帳と役割が重なる。E から開けず見つけにくい |

- A でも、枠にマウスを載せたときの説明（品名・使い方・今の状態）は名札の右に出す。袋に何も入っていない最初のときは「ここに、旅で手に入れた大事な品が自然に入る」と一行だけ出す。
- 色の印は控え帳と同じ（青緑＝あり、灰＝まだ、金＝使える）。見た目は 32px 密度、骨の枠・石板は装飾・共鳴の炉と同じ。
- まだ手に入れていない品（袋に入れたことがない）は枠に「？」、名札は「？？？」。いちど手に入れて今は 0 の品は暗い影。
- 画面の右上の「作り直し」で、枠の部分が作り直しの一覧（16.4）に切り替わる（「もどる」で戻る）。
- 持ち物の枠は出さない。枠の動かし方（16.2）。

### 9.3 レシピ本と他の mod

- 袋の画面は `InventoryMenu` と別（`PouchMenu`・`PouchScreen`）。レシピ本は持ち物の画面の部品なので、袋の画面には出ない。持ち物から袋へ移るときにレシピ本は閉じる（開いたままだと画面が右へ寄ってつまみがずれる。装飾と同じに追従させる）。
- つまみは持ち物の画面の**上の端**に付ける（左右は他の mod が使う）。つまみの数は `RpgTabs` に任せ、持ち物の画面に足す他の mod のつまみと重ならないよう、左端から並べる。
- JEI などの「アイテムを探す」画面は、袋の画面でも右に出る。袋の枠は JEI の「レシピを置く」の対象外（`mayPlace` で拒む）。
- ほかの mod の品は袋に入らない（品の ID が登録にないため）。他の mod の「持ち物を自動で整理する」ボタンは、袋の枠を動かせない。

### 15.0 親スイッチ（既定は入）

ゲームルール `skyabyssPouch`（`PouchConfig.enabled()`。既定は入、`ENABLED_DEFAULT`）で全体を止められる。切の間は、拾う入口・掃除・移し替え・`PouchRouting.give` の袋行き（`Pouch.add` が 0 を返し、昔の渡し方になる）をしない。読む側（炉・クエスト・控え帳など）は袋の中身を数え続ける（空なら無害）。袋に入った品は、切にしても失われず、`/skyabyss pouch take` で出せる。**前の版のワールド**はゲームルールが「切」で保存されているので、最初の起動で一度だけ既定（入・取り出し不可）へ書き換える（`PouchSetup.WorldState` の `ruleApplied`。そのあと管理者が切にしたものは戻さない）。ログインの移し替え（`PouchMigration.onLogin`）は、袋が入になった世界で、`migrated` が版に届いていない人に一度だけ流れる。

### 15.1 設計からの違いと、確かめた結果

1. **手に持って使う品は、使う入力（P6）ができたので袋へ入れる**（`PouchConfig.USE_TOOLS_IN_POUCH = true`）。手に持たないと使えなかったのは: 呼び笛・呼び貝（`TitanCallItem`）、潮見の貝（`TideConchItem`）、風見鶏（`WeathercockItem`。手に持つと帯に状況も出る）、伝承の書（`LoreBookItem`）、破れた頁（`LorePageItem`。読むと消え、頁ごとに出どころの印を持つので、個数だけの袋に入らない）。`PouchUsable.usePouch` を作って true にした（頁は出どころの印の扱いが残る。16.3）。天の鍵・欠片は、扉も仕掛けも鍵の品を要求しない（手に持つと足もとで脈を打つ演出が画面にあるだけ）ので袋に入れてよい。
2. **火の鍵は焼き入れの前も後も袋に入れない**。22 の 2.1 は「火の鍵（焼き入れ後）」を袋に入れるとしていたが、鍛え手の扉は手に持った鍵で開け（`Forge`）、背中を出ると取り上げられ（`EmberTrials`）、余燼の蛾が手に持つ人へ寄る（`EmberMoth`）背中の試練の道具なので、2.2 の側に寄せた。
3. **「潮の真珠」は袋に入れない**。登録の `tide_pearl` は潮の庭の試練で運ぶ品（`TideGarden`）。2.1 の「潮の真珠」は、潮干しの貝（小さな素材）などの意味に読み替えた。
4. **袋に入るのは部品のない品だけ**。強化・名前・特性などの部品が付いた品は持ち物に残す（8.1 の「見本 proto」は持たず、ID と個数だけ）。素材・共鳴・心核・鍵は部品がないので支障はない。
5. **画面（箱など）を開いている間は 1 秒の掃除をしない**。箱から取った品をカーソルで持ったまま消えるのを避けるため。閉じた次の tick に掃除する（22 の 4.1 のとおり）。クリエイティブも掃除の対象（4.4 の `hold` は管理者のコマンドで入れた）。
6. **レシピ（作業台）は持ち物の品を使う**。素材・共鳴・心核は袋にあって作業台に並べられないので、袋の画面の「作り直し」で作る（16.4。呼び笛の作り直しも）。
7. **進捗（advancement）**: 袋の品を条件にしている進捗は今ない（`inventory_changed` で見ているのは炉のブロックと伝承の書だけ。書は袋に入れていない）。初めて袋に入れたときに `Beats.fire("pouch:<品の名前>")` を送るので、進捗を足すときはこれを使う。
8. **控え帳の仮の行は足していない**。袋の中の品は在りかの行（「旅嚢 ×n」）に出るので足りる。袋の全体の一覧は旅嚢の画面。

## 16. 画面・使う入力・作り直しの実装（P4・P5・P6・P9・P10）

### 16.1 つまみと画面

- **つまみ**: 持ち物 / 装飾 / 旅嚢 の三つ。`AccessoryScreen.addTabs`（持ち物の画面・装飾の画面・旅嚢の画面が同じ関数で足す。選ばれたつまみは押せず画面の縁とつながる）。位置は毎回、画面の左端から決めるので、レシピ本を開いて持ち物の画面が右へ寄っても付いていく。旅嚢のつまみはサーバーへ `PouchNet.Open` を送り、`PouchSetup.openMenu` が `PouchMenu` を開く。クリエイティブの持ち物の画面にはつまみを足さない（装飾と同じ既知の制限）。キー I でも開く。
- **画面**: `client/pouch/PouchScreen`（176×200、`textures/gui/pouch/pouch.png`）。区分の名札つきの固定枠（`PouchLayout`: 九列に流し込み、小さな区分は前の行の空きに置く。品が増えて枠の並びが説明の線を越えたら自己テストが止める）。枠の絵は金（使える道具）・青緑（あり）・空。まだ入れたことのない品は「？」、いちど入れて今は 0 の品は暗い影。下の説明は、枠にマウスを載せると品名・数 / 上限・使い方、載せていないと「倒れても残り、落とせない」（空なら最初の案内）。
- **メニュー**: `PouchMenu`。枠は品ごとに 1 つ（袋の数を映す見かけの品。個数は 999 まで表示）。持ち物の枠は出さない。枠の標準の動き（置く・取る）は全部断り、`clicked` がサーバーで決める。クライアントは何も予測しない（サーバーが数と持っているカーソルを返す）。

### 16.2 枠の動かし方（シフトクリックなど）

| 操作 | 結果 |
| --- | --- |
| カーソルに品を持って枠を左クリック | その枠の品なら全部入れる（上限まで。入りきらない分はカーソルに残る）。枠と違う品は何も起きない |
| 同じ・右クリック | 一つ入れる |
| カーソルが空で枠を左クリック | 一スタック取り出してカーソルへ。**取り出せるとき（`skyabyssPouchWithdraw` が 1 で、共鳴・素材・小さな素材の区分）だけ**。「取り出し済み」の印が付く。鍵・心核・笛・書・欠片は出ない |
| 右クリック | その半分 |
| シフトクリック（枠） | 取り出して持ち物へ（同じ決まり）。持ち物の枠は出さないので、持ち物から袋へのシフトクリックはない（拾えば自動で入る） |
| 投げる・数字キー・ダブルクリック・画面の外 | 何も起きない |
| 管理者 | `/skyabyss pouch take <品> [個数]` は決まりを無視して出せる |

### 16.3 使う入力（P6）

- **キー**: Y（長押し = 輪、短押し = 左の札の道具。札が切なら前回の道具）、I（画面）。`client/pouch/PouchClient`。長押しの境は 4 tick（0.2 秒）。
- **輪**: `client/pouch/PouchWheelScreen`。袋にある使える道具（`PouchUsable.usable`。登録の順）を円に並べ、マウスの向きで選び、キーを離すと使う。中心で離す・Esc で取りやめ。札をクリックしてもすぐ使える。道具が 1 つなら輪を出さずに使い、0 なら「使える道具が旅嚢にない」を一度出す。ゲームは止めない。
- **サーバー**: `PouchNet.Use(Optional<ResourceLocation>)`。サーバーが `PouchUsable.usePouch(player, item)` を呼ぶ（袋にあるか・親スイッチ・待ちを見る）。品の空は「前回の道具」（サーバーも覚える）。結果は `PouchUsable.Result`（OK / REFUSED / NONE / COOLDOWN）。
- **一枚札**（`client/pouch/QuickCard`・選び方は純粋な関数 `pouch/QuickPick`）: ホットバーの左手の枠のある側（左利きなら右。左手の品が出ていればその外側に間をあけて）に、短押しで使う道具を 1 枚だけ出す。ホットバーと同じ枠の絵、上にキー名（今の割り当て）、数が 2 以上なら数。入れ替わった直後は金の縁と道具名を少しだけ出す。場面の最中・画面を開いている間・F1・デバッグ画面では出さない。
  - 自動の選び方（上が優先）: 置いた札 > 巨神の乗り場（標の 6 ブロック）・巨神（128 ブロック以内）のそば = その巨神の呼び笛・呼び貝（乗り場だけなら前回の笛・貝）> 海の上（水中・水面・潮殻・ボート）= 潮見の貝 > 嵐（雨・雷翼が近い）= 風見鶏 > 前回の道具 > 使える品の先頭。その場面の道具を持っていなければ次へ落ちる。
  - 置く: 旅嚢の画面で使える道具の枠を右クリック = 置く／はずす（枠の角に金の点）。輪で選んで使った道具も置かれる。置いた道具は、はずすか旅嚢から無くなるまで自動より優先する。置いた名前はクライアント設定 `pouchQuickPin` に残る。
  - クライアント設定 `pouchQuickCard`（既定 入）。切ると札は出ず、短押しは前回の道具（なければ先頭）。サーバー側は何も増えず、使うのは既存の `PouchNet.Use`。
- **共通の入口**: `PouchUsable`（インターフェース）。`TitanCallItem`・`TideConchItem`・`WeathercockItem`・`LoreBookItem`・`LorePageItem` が実装し、右クリック（`Item.use`）も旅嚢の輪も同じ `usePouch(ServerPlayer, Runnable consumeOne)` を通る。待ち・条件・音・効果は右クリックと同じ。伝承の書は `PouchNet.OpenBook` で持ち主の画面に書を開かせる。破れた頁は使えたときに袋の数を一つ減らす。
- **頁だけ例外**: 出どころの印（`PAGE_SOURCE`）が付いた頁は、部品のある品なので袋に入らない（持ち物に残り、右クリックで読む）。印のない頁だけ袋に入り、輪から読める。

### 16.4 作り直し（205）

- 右上の「作り直し」で一覧。`PouchRebuild.recipes` は、作業台のレシピのうち**材料に袋の品が一つでもあるもの**を、レシピ ID の順に並べる（クライアントとサーバーで同じ並びで、メニューのボタン番号 = `BUTTON_RECIPE_BASE`＋この並びの番号）。今の対象: 呼び笛・呼び貝（`stone_whale_call`・`tide_shell_call`）、標（`titan_waymark`）、共鳴の炉（`resonance_forge`。結晶と鱗片）、燠の灯（`cinder_lamp`。燠の殻）、花火（`firework_rocket_from_spark_dust`。火の粉の粉）、温石（`warm_stone`。余燼の欠片）。袋の品を使うレシピが増えれば自動で並ぶ（登録のし直しは要らない）。
- 一覧に出す人: 材料の袋の品を、どれも一度は手に入れている（`PouchData.seen` か数がある）。まだ知らない品を明かさない。
- 材料は **袋から先に、足りなければ持ち物から** 払う（骨など袋にない品は持ち物から）。できた品は `PouchRouting.giveOrDrop`（袋に入る品は袋、残りは持ち物、入りきらなければ足もと）。足りなければ何も払わず「材料が足りない」を帯に出す。サーバーが決める（`PouchMenu.clickMenuButton`）。
- 作業台そのものは変えていない。袋の品は持ち物に出ないので、作業台でこれらのレシピは作れない。**袋の品を材料にする作業台のレシピは、すべてこの一覧で作る**（ほかの mod が足したレシピも、材料に袋の品があれば並ぶ）。
- **修理**: 一覧の下の「修理」で、手に持った壊れた品を袋の素材で直す（金床は袋の品を並べられないため）。その品の `isValidRepairItem` を満たす袋の素材を使い、一つで最大耐久の 1/4（金床と同じ）。
- **ほかに持ち物を要るもの**: 金床での修理・合成は、袋の品を並べられない。修理は上の「修理」で済ませる。鍛冶や炉は袋から直接払う（8.3）。
