# 岩鯨と背中の試練 完成度レビュー

- 対象: 岩鯨（StoneWhaleEntity）、岩鯨の背（titan_back）、三つの試練、番兵長（中ボス）、岩鯨の心臓（最終ボス）、報酬と巨神の記憶
- 基準: `docs/design/02_stone_whale.md`、`docs/design/03_gear_and_endgame.md`（3.1節・2.3節・7章）、`docs/roughs/IMPLEMENTED.md`
- 対象のコード: ブランチ `m1-sky-pass` の HEAD（af8ac23）。レビューの時点で `src/main/java` に未コミットの変更はない
- 方法: コードを読んで、プレイヤーの流れを最初から最後までたどった。加えて、足場の生成器と迷路の生成器をゲームの外で動かして調べた（足場は 5000 種で生成の失敗が 0 件、1 種あたり約 6 ms。迷路は 2000 種で、条件に合う形が出るまでの試行が平均 115 回、最大 880 回）
- 実機では確かめていない。「要実機確認」と書いた項目は、仕組みから判断したもの

---

## 1. 結論

**完成としてよいか: いいえ**

一人で、コマンドを使い、途中でゲームを止めずに遊ぶ流れは、端から端まで成り立っている。乗り込み、三つの試練、共鳴石、宝物庫と奥の扉、心臓の 3 段階、報酬、光の柱、3 分後のリセットまで、仕様書 02 とほぼ一致する。

ただし、次の問題があるため、まだ「完成」とは呼べない。

- 自然に湧いた岩鯨に出会えない。
- 試練を飛ばして心臓へ行ける抜け道がある。
- マルチプレイで、扉が仲間を締め出す。
- 倒れたあとに持ち物を失うことがある。
- 保存して終了すると、ボスが二体になる。
- 鼓動の間で復活すると、柱の中に埋まる。
- ピースフルでは進めなくなる。
- 仕様書 02 が今の実装と食い違う。

どれも、直し方ははっきりしている。下の M1〜M8 を直し、実機で確かめれば、「完成」と言ってよい。

## 2. 完成と呼ぶ前に直すもの（must-fix）

### M1. 岩鯨が処理範囲の外で止まり、自然には出会えない（要実機確認）

- 根拠
  - 出現は、プレイヤーから 280 ブロック先（`titan/TitanEvents.java:52`）。巡航の目的地は、プレイヤーから 120〜260 ブロック先（`titan/StoneWhaleEntity.java:280-293`）。
  - 岩鯨は普通の Entity で、チャンクを読み込んだままにする仕組み（チケットや強制読み込み）がどこにもない（grep で確認）。
  - マイクラでは、エンティティはシミュレーション距離の内側でしか tick しない。初期値は、専用サーバーで 10 チャンク（約 160 ブロック）、シングルで 12 チャンク。
  - そのため、出現した直後の岩鯨は動かない。降下までの待ち時間 `restCooldown`（`StoneWhaleEntity.java:160`）も減らない。巡航中も、目的地が範囲の外にあると、範囲の端で止まる。
  - 出現は一度きり（`TitanEvents.java:62` の `spawned`）。このため、プレイヤーが遠くへ移動したり、岩鯨が止まったまま保存されたりすると、二度と出会えない。テストのときは `titan summon`（120 ブロック先）を使うので、この問題は表に出にくい。
- 直し方
  1. 岩鯨のいるチャンクに、時間切れ付きのチケットを毎秒張り直す。例: `TicketType.create("skyabyss_whale", …, 40)` と `addRegionTicket(…, 2)`。張るのは、640 ブロック以内にプレイヤーがいる間だけにする。
  2. `TitanWorldData` に岩鯨の UUID と最後の位置を保存する。オーバーワールドのプレイヤーの近く（例: 640 ブロック以内）で一定時間 tick していなければ、近くへ呼び直す。古い個体は、読み込まれた時点で UUID を見て消す。
  3. 出現する距離と巡航の目的地を、シミュレーション距離の内側（例: 100〜150 ブロック）に収める案もある。

### M2. 休み場の記録が消えず、試練を飛ばして心臓と戦える

- 根拠
  - 休み場の記録 `skyabyss_checkpoint` は、死んでも消えない領域に書かれる。書き込みはあるが、消す処理がどこにもない（`titan/dungeon/TitanBackTrials.java:541-543`）。乗り込み（`TitanTravel.java:106-122`）、焚き火であきらめるとき（`TitanBackTrials.java:645-651`）、リセット（`TitanBackTrials.java:462-486`）のどれでも消さない。
  - その結果、前回 `heart`（心臓の前室）まで行った人は、リセット後に島のどこで倒れても、心臓の前室で目を覚ます（`TitanBackTrials.java:614-625`）。そこは閉じた奥の扉の先なので、三つの試練を飛ばして心臓と戦い、天の鍵の欠片と装備を得られる。記録が `ce2` でも、東の二つの広間を飛ばせる。
  - 同じように、奥の区域（宝物庫より先や心臓の回廊）でログアウトし、リセットのあとにログインすると、そこから始められる。
- 直し方
  - `TitanBackData` に、リセットのたびに増える番号を持たせる。休み場の記録にもその番号を一緒に書き、番号が違えば記録を無効（尾の台）にする。
  - 乗り込み、地上へ戻るとき、焚き火であきらめるときにも、記録を消す。
  - ログインしたときと、背中のディメンションに入ったときに、番号が古く、しかも封印の先にいる人は、尾の台へ移す。

### M3. マルチプレイ: 最初の一人で扉が閉じ、仲間が締め出される

- 根拠
  1. 広間（`TitanBackTrials.java:214-222`）も心臓の間（`:341-344`、`:377`）も、一人目が内側に一歩入った瞬間に入口を封じる。後ろにいる仲間は入れない。戸口に立っている人の位置に封印のブロックが置かれ、閉じ込められることもある。
  2. 人数による増加は、封じた瞬間に中にいる人数で決まる（`:217`、`:284`）。そのため、実際にはほぼいつも 1 人として数えられ、仕様書 02 の 4.2 節の表は働かない。
  3. 広間を制圧しても、出口しか開かない（`:251-254`）。戦いの途中で倒れて前室（`e0`/`ce1`/`ce2`）で目を覚ました人は、制圧のあとも入口が閉じたままなので、先へ進めない。焚き火であきらめるしかない。
  4. 番兵長の広間（E3）には出口がない。制圧のあと、共鳴石を鳴らす前に中の人が倒れると、東の石に二度と届かない。島から全員が去って 3 分たつまで、この状態が続く。
- 直し方
  - 内側に入ったら、すぐ閉じずに 5 秒の予告（「扉が閉じる…」）を出す。閉じる瞬間に、前室と戸口にいる人も中へ移して数える。
  - 制圧したら、入口も開ける。一方通行にこだわるなら、前室で目を覚ました参加者だけを、制圧した広間の出口側へ送る。
  - 心臓の間は、戦いの参加者（`heartParticipants`）が倒れて前室で目を覚ましたとき、扉の内側へ戻れるようにする（または戦いの間だけ、参加者は通れる封印にする）。

### M4. 倒れたときの持ち物は、メモリにしか残らない（失うことがある）

- 根拠
  - 倒れた人の持ち物と経験値は、静的な `KEPT` の Map にだけ置かれる（`TitanBackTrials.java:94`、`:572-577`）。地面にも落ちない（`:580-592`）。
  - サーバーが止まると、この Map は消える（`:161`）。シングルで、死亡画面のまま「保存して終了」するだけで、持ち物と経験値をすべて失う。一方で、死んだ記録の印（`TAG_DIED_ON_BACK`）は残るので、次に入ったときは背中で目を覚ますが、持ち物は空のまま。
- 直し方
  - 預かり物を、プレイヤーの永続 NBT（`PERSISTED_NBT_TAG`）か SavedData に書く。`Clone` で戻したあとに消す。
  - あわせて、消滅の呪いが付いた物は、バニラと同じく消す（N9）。

### M5. 保存して終了（再起動）すると、心臓や番兵が二重に出る

- 根拠
  - 起動後の片付け（`TitanBackTrials.java:180-189`）は、背中のディメンションが最初に tick したときに一度だけ動く。そのときはプレイヤーがいないので、闘技場のチャンクが読み込まれておらず、`getEntitiesOfClass` で何も見つからない。
  - 心臓（`entity/StoneWhaleHeart.java:117`）も番兵（`TitanBackTrials.java:314`）も「消えない」設定なので、ディスクに残る。
  - そのため、次に人が来ると、残っていた心臓と新しく湧いた心臓の二体と戦うことになる。残っていた方を倒すと `onHeartDefeated` が報酬を配るが、新しい方はそのまま残る（`TitanBackTrials.java:407-418` は、すでに撃破済みなら何もしない）。
  - 広間でも、残った番兵の上に第一波が湧く。E3 では番兵長が二体になり、中ボスの報酬も二回出る。
- 直し方
  - 心臓と、試練で湧いた番兵を保存しない。`shouldBeSaved()` を上書きして false を返す。あるいは `EntityJoinLevelEvent` で、ディスクから読み込まれ、`MOB_TAG` か `HEART_TAG` が付いた個体を取り消す（戦いの状態はメモリにしかないため）。
  - あわせて、`StoneWhaleHeart.die` で、背中のディメンションにいて `HEART_TAG` が付いた個体だけが撃破を報告するようにする（N8）。

### M6. 鼓動の間の休み場で目を覚ますと、強化深層岩の柱の中に埋まる

- 根拠
  - 休み場 `hub` の復活位置は `HUB.center()` で、(0, 94, -22) になる（`TitanBackTrials.java:80`、`TitanBackLayout.java:37`）。
  - そこには、「眠る心臓の台座」として強化深層岩が 2 段置かれている（`TitanBackBuilder.java:473-474`）。
  - 迷路を泳いでいる間は、記録が `hub` になる。水路で溺れたり水路の顎に倒されたりして目を覚ますと、柱の中で窒息する。
- 直し方
  - 復活位置を、例えば `HUB.center().offset(0, 0, 6)` へ移す。
  - 自己テストに「休み場の復活位置の足元と頭が空いている」検査を足す（N7）。

### M7. ピースフルでは心臓が消え続け、先へ進めない

- 根拠
  - 心臓、番兵長、番兵はどれも Monster で、`shouldDespawnInPeaceful` を上書きしていない（grep で確認）。
  - ピースフルでは、心臓が湧いた直後に消える。すると `tickHeart` が「撃破の報告なしに消えた」と判断して扉を開け（`TitanBackTrials.java:347-351`）、10 tick 後にまた封じて湧かせる。この繰り返しで、チャットに「眠った」の知らせが流れ続け、天の鍵の欠片は手に入らない。
  - 広間では、番兵が消えるので戦わずに制圧され、番兵長の報酬も出ない。
- 直し方（どちらか）
  - 試練の番兵と心臓で `shouldDespawnInPeaceful()` を false にする。
  - ピースフルのときは、入口に「難易度を上げないと巨神は目を覚まさない」と出して、入れなくする。
