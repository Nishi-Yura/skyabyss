画面の部品を整理する

試遊の声: 「チュートリアルの文字と、Jキーを押そう・Uキーを押そうが重なっている。UI 関係全体を整理して、デザインした方がいいところがあれば案を」。原因は、各部品が自分で座標を決めていて、お互いを知らなかったことでした。今回は、置き場を決める一つの司令塔 (HudManager) を作り、どの部品もそこから長方形をもらって描くようにしました。仕様は docs/design/18_notices.md の 9 章。

直ったところ（撮影した画面）

並べ方と優先のきまり

左上の帯（上から下へ）章の名前（枠だけ確保）→ 成長（Lv・経験値）→ 技の枠 → 目的の帯 → 追跡中の依頼。入らなければ、いちばん下の部品から出さない
右上の板（上から下へ）効き目の絵と札（トースト）の下から: 誓い → 背の目盛りと目的の板 → 仲間の一覧。札が出入りしても、板はなめらかにずれる
上中央（ボスバーの下へ）ボスの技の名前 → 上の帯（場所・章・戦いの知らせ）→ レベルアップ → 中央の一行。照準のまわりには伸びない
下中央（アクションバーの上から上へ）倒れた表示 → 手がかり（初回の案内・キーの手がかり・できた）→ 字幕。字幕は一行ぶんを必ず残し、足りなければ行数を減らす
ホットバーの左右旅嚢の札・成長・技の枠を外側へ並べる。オフハンド・攻撃の目盛りの先から。入らない狭い画面では左上へ逃がす
隠す場面と、重ならない保証F1・場面（カメラの演出）では全部隠す。計算は純粋な長方形の計算で、GUI 倍率 1〜4 × 16 種の窓で重なりがないことを自己テストが確かめる

見た目を決めてもらう（3 案）

置き場の整理は見た目に関係なく入れました。ここは「板・文字・キーの表示の絵柄」を揃えるかどうかです。下の見本は同じ場面（序盤: 手引きの 2 行 + 字幕 + 目的の帯 + ボス戦の一部）を三つの絵柄で描いたもの。推薦は A（いまの延長。壊さず整える）。
