# キューブの geo と絵の棚卸し (2026-10-24)

目的: 低ポリ (LowPoly.enabled = true) が既定の今、通常のプレイでは使われないキューブの素材を通常のジャーから外す。
外したものは `tools/sources/geo_cube/` にある (同じ相対パス)。戻すのは `python tools/dev/cube_geo.py back`。

## 移した素材が通常のプレイで使われないと言える根拠

移したキューブの素材を読む所は、すべて `LowPoly.enabled = false` のときだけの分岐 (または使われていない死んだ分岐)。
通常 (有効) の描画は低ポリの骨・絵だけを読む。

- `LowPolyGeoRenderer.Model` (低ポリの通常の模型。NPC・番兵・Ch1〜4 の地上の敵・ボスの段など多数が使う) : 有効なら `_lowpoly` の骨と `textures/lowpoly/` のアトラス、無効なら元の geo と絵。
- `LowPolyLodModel` (巨神の 3 段: 岩鯨・潮殻・雷翼・余燼): 同上。
- 心臓 4 種 (余燼・雷・潮・岩鯨): `_pN` の geo と絵は無効時のみ。
- 灰被り (`ash_husk`・`elder_thrall`): 有効時は `ash_thrall_lowpoly` の骨 (この 2 つには `_lowpoly` の geo は無い)。キューブの `ash_husk` 等は無効時のみ。
- 山羊・番人・鍛え手などの個別の描画: 下の表。
- 死んだ分岐 (呼ばれていない): `GuardRenderers.geo(...)` と `TideMobRenderers.MobRenderer` は `DefaultedEntityGeoModel` でキューブを直接読むが、呼び出し元が無い。消してはいない (触るのは別の仕事)。

## 残した素材と理由

- `geo/entity/*_lowpoly.geo.json` (297 本): 有効時の骨。
- `geo/entity/*_lowpoly_debug.geo.json` (131 本・約 0.22 MB): `LowPoly.debug` (骨の箱の重ね) と BossRender の無効時の代わり。小さいので残す (移すと debug が必要な時に落ちる分岐が増える)。
- `lowpoly/*.json` (221 本・約 30 MB 生): 低ポリのメッシュ。通常のプレイで毎回読む。
- `textures/lowpoly/` (490 枚): 低ポリの絵と発光マスク。
- `animations/` (135 本): 全部。骨の名前は低ポリと共通。
- `geo/gear/`・`geo/armor/`・`textures/gear/`・`textures/armor/`: 武器・防具の模型 (キューブの geo ではない)。

## 無いときの振る舞い (LowPoly.cubeOr / cubeHere)

`LowPoly.enabled = false` のとき、キューブの素材が無ければ落ちずに低ポリのまま描き、素材ごとに一度だけ警告を出す
(`[lowpoly] cube material missing, keeping the low-poly look: ...`)。LowPolyMeshes の再読み込みで判定の表を空にする。
キューブの比べ (台本の `lowpoly off`) をするには、先に `python tools/dev/cube_geo.py back` で戻す。

## 検証

- コンパイル: `./gradlew --no-daemon --offline -q compileJava` 成功。
- 生成スクリプトのドリフト: `PYTHONPATH=tools/lib python tools/audit/check_generators.py` → drift/fail 0。
- 自己テスト: `group:mobs,group:titan,group:backs` で 59 件 PASSED、2 件 FAILED (余燼の地上の箱の数。キューブの箱の数を
  低ポリの骨から数えていたテストの誤り)。テストを直し、`ember surface` だけ再実行して PASSED。キューブが無いときは箱の数の検査を飛ばす。
- 撮影 (runShots): 12 台本 (lp_titan_whale・lp_titan_tide・lp_titan_storm・lp_titan_ember・lp_heart・lp_npc・mounts_v2・ch2_mobs・
  hp_midboss・lp_storm_raiju・lp_ember_thrall・lp_tide_beckoner) を移す前後で撮った。
  - 生成の揺れ: 同じ前の木で二度撮ると、62 枚のうち 57 枚が一致しない (中央値の平均差 0.11)。撮影は決定的でない。
  - 前後の比べ: 中央値の平均差 0.19、一致 1 枚。一部の台本は、オープニングのムービーや選択の画面の時刻がずれ、
    別の場面を撮っている (例: lp_titan_ember の近景は、前では対話、後では「天職を選ぶ」画面)。その枚数は大きな差になる。
  - 結論: 画面の同一性はピクセルの比べでは証明できていない。ずれていない枚は揺れの範囲に収まる。見た目が変わらないことは
    コードの経路 (上の表) と、同じ場面を撮れた枚の揺れの範囲で確かめた、という扱い。
- ログ: 移後の撮影ログに GeckoLib の例外・素材の欠落の例外は無し。警告は「キューブの素材が無い」の一種だけ
  (台本の `lowpoly off` の区間で出る。意図した動き)。
- 読み込みの時間: 撮影ログからは計れなかった (測っていない)。
