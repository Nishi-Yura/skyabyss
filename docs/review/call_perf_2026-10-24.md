# 呼びの探しの時間 (2026-10-24)

測り: `CallPerfSelfTest` (SKYABYSS_SELFTEST_ONLY="call perf")。専用サーバーの実行で、`CALLPERF` の行に出す。
読み込まれた地形は spawn のまわり、読み込まれていない地形は spawn から 1400 ブロック遠く (三点)。

## 最初に分かったこと

- 呼び笛 (`TitanCallItem`) が実際に使うのは `YoungCarriers.whistle` → `findSpot` (子の出る所)。
  成体の `TideOcean.findCallSpot` / `EmberGround.findCallSpot` / `callNear` は、呼び笛からは呼ばれていない
  (`callNear` は定義だけで呼び手がない。`EmberTitanEntity` の口の待ちからだけ `EmberGround.findCallSpot` が動く)。
  このため、笛は「一度 0.2〜0.7 秒」の経路ではなかった。
- 同期の区画読み込みで止まるのは、背中から戻る探し `TideOcean.standableShore` と `EmberGround.landingAt` (生成が起きる)。

測った点の最大は 2.8 ms。

## 直したこと

1. 笛・成体の探し: 変えていない (測りで 20 ms 未満)。結果も変えていない。incremental 化はしない。
2. 戻る探し (`TideOcean.standableShore`、`EmberGround.landingAt`): 中身は変えず、呼び手だけ変えた。
   - `jp.revati.skyabyss.util.ChunkWait`: 探す範囲の区画が「完成」しているかを読み込まずに見る (`getChunk(..., FULL, false)`)。
     足りなければ区画の券を出し、`later` で準備ができてから (最長 200 tick、過ぎたら同期で探す) 同じ探しを流す。
   - 呼び手: `TideTravel.leave` (岸の中心は `shoreCenter`)、`EmberTravel.leave` (出口は `exitCenter`)。準備ができるまで背中にいる。
   - `TideShellEntity` の乗り場 (`shoreDock`): 区画が揃うまで「乗り場なし」で待ち、揃ってから探す (tick ごとに再確認)。
   - 結果は同じ関数を、区画が読み込まれた後に呼ぶので、同期の探しと同じ (self-test で確認)。
3. 残っている同期の経路: `TitanEnd.landing` の潮殻の分岐 (`SafeSpot` が見つからないときの `standableShore`)、
   `SafeSpot.find` の読み込み。今回は直していない。

## 直した後

- 待つ探し (`CALLPERF wait`): 待った探しは 0.03 ms (区画は待つ前に読み込み済み)。同期の探しと同じ結果 (`same as now: true`)。
- 注意: この run の遠い三点は前の run で生成済みだったため、直した後の「読み込まれていない地形」の数は生成を含まない
  (前の run の 688〜1274 ms が生成の時間)。生成ありの直した後の待ち時間は、新しい世界での全体 run の `CALLPERF wait` 行で見る (下の結果)。

## 検証

- `SKYABYSS_SELFTEST_ONLY="call perf"`: PASSED (測り)、PASSED (待つ探し)。
- 全体 (雛形の世界から、`rm -rf run/world; SKYABYSS_SELFTEST=1 bash tools/dev/mc_run.sh runServer`): **173 PASSED / 0 FAILED**、BUILD SUCCESSFUL。
  - 最後の run の数: 読み込まれた地形の戻る探し (tide shore) max 0.37 ms、ember landing max 1.10 ms (同じ世界で区画が既に読み込まれていた)。
    読み込まれていない地形の同期の探し (tide shore) は 2.1 秒 avg / 2.9 秒 max で、これは直す前の同期の探しの時間を測っているだけ (実際の経路では ChunkWait で待つ)。
  - 待つ探し: 40 tick 待って、0.02 ms で完了、同期の探しと同じ結果。
- 途中の失敗について: 雛形 (`tools/dev/world_template.sh`) は `titan/` 配下のソースで鍵が決まり、この変更で鍵が変わった。雛形がないまま run すると、ch1 の背 (`ch1 back mobs`) の老番兵の突進が 5 件失敗した (雛形なしでの単独 run でも同じ)。
  `world_template.sh make` で雛形を作ると単独も全体も通った。これは変更の不具合ではなく、雛形の欠落による (origin/m1-sky-pass の worktree での単独 run は通った)。
