# 夜の統合レビュー (要素どうしのつなぎ目)

対象は `346b07c..HEAD`（成長、技、伝承の書、序章の見る者、NPC とクエスト、装備の特性・再鍛造・交換、1章の空、巨神での移動）。
観点ごとに読み手を分け、上がった指摘はすべてコードで確かめ直した。推測の段階にとどまるものは「直していない」に回した。
直したあと `./gradlew compileJava --offline` と `SKYABYSS_SELFTEST=1 ./gradlew runServer` を通した（9 系統すべて PASSED）。

## 直したもの

| # | 要素 | 不具合 | 原因（確かめた箇所） | 直し方 | 自己テスト |
|---|---|---|---|---|---|
| 1 | 成長 × 特性 | 活力（最大体力）の防具を着ていると、ログインのたびに体力が「装備なしの上限」まで減る。復活したときも満タンにならない（例: 20/30） | 装備の修飾子は保存されず、ログイン・復活のあとの最初の tick で付く。バニラは読み込みのときに体力を今の上限で切り詰める（`LivingEntity.setHealth` の clamp）。`GrowthRewards.onRespawn` も、装備の修飾子が付く前の上限で満たしていた | `GrowthRewards` で体力を 1 秒ごとと、ログアウトのときに persistent data（`skyabyss_health`）に覚える。ログインで切り詰められていたら、最初の tick（装備の修飾子が付いたあと）に戻す。復活のときもその tick にもう一度満たす | なし（本物のログインと装備の見直しが要るため。実機で確かめること） |

## 確かめて問題がなかったもの（主なもの）

| 観点 | 結果 |
|---|---|
| サーバーとクライアントの分離 | 共通側からクライアントのクラスを呼ぶのは、各 `*Network` の playToClient のハンドラ（ラムダ）と `LoreBookItem.use` の `isClientSide` の分岐だけ。専用サーバーではどちらも通らない。クライアントのクラスの購読はすべて `Dist.CLIENT` |
| Data Attachment | 成長・技・伝承・NPC の好感度・クエスト記録・移動の 6 種類に、保存と copyOnDeath がそろっている。エンドからの帰還ではすべてが写される。同期する 4 種類は NeoForge がログイン・復活・ディメンション移動のときに送る |
| 古いセーブ | 各 Codec は optionalFieldOf を使っている。保存された文字列を valueOf や getOrThrow に渡す箇所はない。消えた技・クエスト・伝承の ID はすべて null で受けている。特性のない古い装備も has や getOrDefault で扱っている |
| 修飾子の ID | 成長（`growth/*`）、特性（`affix/<type>_<slot>`）、強化（`enhance*`）、補強板（`plating_*`）、技（`skill/stone_stance_*`）、槍の間合いは重ならない。どれも addOrReplace か差分の付け直しで、毎 tick 積み上がるものはない |
| 経験値の二重計上 | 撃破の経験値は `GrowthRewards.onDeath` だけが配る（クエストは進み具合だけ）。番兵長と心臓は参加者に一度ずつ配る。飼い慣らした動物の撃破は飼い主に一度。初回・バイオーム・次元・休み場・クエストは、別々のキーで一人一回 |
| 傷の計算 | 敏捷・技・守りの補正はそれぞれ今の値に掛けるので、互いに上書きしない。技の傷から特性へ回って再び傷を入れる再帰はない。技は無敵の NPC と岩鯨（LivingEntity ではない）に当たらない |
| キー | J・K・U・R・G・V・Z は、どれも mod の中でもバニラ 1.21.1 の既定とも重ならない（IN_GAME）。画面が開いているときは動かない |
| HUD | 成長（左上 y 6〜21）、マナ（y 24〜28）、技の枠（ホットバーの右か左上 y 32〜52）、クエストの追跡（y 71〜）は重ならない。F1 と F3 で隠れる。伝承とクエストの知らせはバニラの札（右上）を使う |
| ログアウト時のクライアントの状態 | クエストの目録、伝承、見る者、怯え、帳（20 秒で自動で下りる）は消すか、自然に戻る |
| 受信パケットの検査 | 会話の選択、技（枠の範囲、未知の ID）、伝承の既読、移動（parseLong を捕捉）、見る者・雲の目の終わり、炉のボタンの番号、どれも範囲の外の値で落ちない。ハンドラはサーバーのスレッドで動く（既定の MAIN） |
| 二人同時 | 会話のセッションは UUID ごとで、同じ NPC と二人で話しても壊れない。炉の装備の枠は一人ずつ |
| tick | 反復しながら消す処理はどれも Iterator かコピーで回している。毎 tick の重い走査は見つからなかった |
| コマンド | 管理・テスト用のコマンドはすべて権限 2 以上 |
| lang | 4 つの名前空間で ja_jp と en_us のキーの集合が一致する。コード・データ・登録物から参照する 415 件と、動的なキーの系列もそろっている（上の #4 を除く）。書式の引数の数も一致する |

## 直していないもの（理由と提案）

| # | 要素 | 内容 | 直さない理由 | 提案 |
|---|---|---|---|---|
| A | 技 | 技の待ち時間（クールダウン）が死んでも残る（`SkillData` が copyOnDeath で写され、`onRespawn` では反撃の印しか消さない） | 仕様かどうかが決まっていない | 復活で消すなら `onRespawn` に `cooldowns.clear(); globalCooldown = 0;` を足す。00 の未決に入れたい |
| B | 技 | 技を覚えた音（`SkillManager` の SOUND_LEARN）が `level.playSound(null, …)` で周りの人にも聞こえる。レベルアップの鈴は「仲間にも小さく聞こえる」とコメントに書いてあるが、こちらには何も書いていない | 意図かどうかが分からない。害は小さい | 本人だけに聞かせるなら `playNotifySound` にする |
| C | クエスト | `xp` の行動で `once` を書き忘れると、すべてのクエストが `npc:` という一つのキーを分け合い、最初の一回しか経験値が入らない（`Action.java`） | 今のデータでは `xp` の行動を使っていない（報酬は `xp` のフィールドで渡している） | 読み込みのとき、`once` のない `xp` の行動を警告するか自己テストで弾く |
| D | 序章 | 見る者に気づいたかどうかは、クライアントの申告をそのまま信じている | 段階が早く進むだけで、報酬にもほかの人にもつながらない | このままでよい |
| E | 特性 | `Affix` の Codec は `type` と `value` が必須で、壊れたデータではコンポーネントごと読めない | 通常の保存では必ず両方が入る | 気になるなら optionalFieldOf にする（未知の種類はすでに無視している） |
| F | 成長の画面 | 振り分けの仮押しは確定ボタンでしか送られず、J・K・Esc で閉じると黙って捨てられる | 不具合とまでは言えない | 未確定のまま閉じるときに一言出す |
| G | NPC | 鯨追いが二重に出る道筋が理論上ある（出現を調べる半径 40 が、読み込みを確かめる 3x3 チャンクより広い） | 再現していない。鐘の 48 ブロック以内にいれば読み込まれている | 読み込みを確かめる範囲を検索の半径に合わせる |
| H | 炉 | 炉を開いたまま死んだとき、`removed()` で装備が戻るかを確かめられなかった | バニラは死んだときに `closeContainer` を呼ぶので、たぶん戻る | 実機で一度確かめる |
| I | 伝承 | 頁をめくる音（`LoreEvents`・`LorePageItem`）が周りにも聞こえる | 害は小さい | B と同じ方針でそろえる |
