# 死亡ペナルティの案（ベータ感想「全ロスは萎える。取りに行くのも面倒で離脱されたくない」への調査）

- 作成: 2026-10-18。現行仕様は `docs/design/` が正（このページは選ぶための資料で、決まったら該当の書類に書く）
- 前提（今の仕様）: 背中の島で倒れると持ち物と経験値は預かられて失わず、休み場から再開（02 の 7.2・7.3）。**地上の死だけバニラのまま全ロス**で、これが今回の不満の元。大事な品（欠片・鍵・心核・呼び笛）は落下品の守りと呼び戻しがある（11 の 4）。00 の 88「倒れたとき大事な品を残すか」が関連する未決
- 調査の限界: 数値は主に wiki・解説記事の検索結果。公式の一次情報でない。FF・Hades・Lost Ark・Genshin・Zelda の損失の細部は今回の検索で裏が取れなかったため「一般知識・要確認」と明記した（Lost Ark は検索で死亡ペナルティの情報が出ず、表から外した）

### 読み取れること

1. **「物を失う」より「金・耐久・時間を失う」ほうが続けられる。** DQ・Diablo・FFXIV が該当する。
2. **取り戻し型（Souls・墓）は、二度目の死で消えるときに強く憎まれる。** 墓が消えない（Valheim）形は、緊張を残しつつ不満を減らす。時間で消える墓は苦情が出やすい。
3. **選べる設計が長生きする。** WoW（走る／払う）、Terraria（難度を選ぶ）、Valheim（サーバー設定）。
4. **装備と手元の道具は残す**（Core Keeper）と、詰まる事故が減る。
5. **「取りに戻る」の摩擦は、死んだ場所が危険なほど離脱に直結する。** Hollow Knight は影を安全な場所に出して緩和している。

## 2. この mod の案

共通の前提:

- 大事な品（欠片・天の鍵・心核・呼び笛・伝承の書）は、どの案でも**死んでも持ち物に残す**（00 の 88 を「三つとも残す」で決める想定）。落下品の守りと呼び戻しが既にある。
- 背中の島は今のまま（持ち物・経験値は預かり、休み場から再開）。**案は主に地上の死の扱い**を変える。
- ゲームルール名は仮。`skyabyssStoryGate` などと同じく、ゲームルールで切れる形にする。
- 「再利用するコード」は設計書にある名前で書いた。実在と使い方はコードで確認すること。

### 案 A: 墓（Valheim・GraveStone 型）

- **地上**: 死んだ場所に墓が立ち、持ち物と経験値を入れる。墓は時間で消えず、持ち主だけが開ける（設定で他人も可）。位置は控え帳 B に座標で出す。
- **背中**: 今のまま預かり（墓は作らない）。
- **取り戻し**: 墓へ行って開く。二度目の死でも別の墓が立ち、前の墓は消えない。
- **代償**: 取りに行く手間だけ。
- **緊張**: 「装備が地面にある」状態で戻る道中が緊張になる。消えないので焦りは小さい。
- **離脱リスク**: 危険な場所（溶岩、深層、夜）で死ぬと、素手で取りに戻る無理ゲーになる。
- **マルチ**: 持ち主限定が既定。仲間が開けて渡せる（設定）。
- **実装**: M。`DropLedger`（落下品の座標控え）、`Keepsakes`（在りかの数え方）、控え帳の「地面に落ちている」行を使える。墓ブロックとその保存だけ新規。

### 案 B: 持ち物は残し、代償だけ払う（DQ・Diablo 型）

- **地上**: 持ち物と経験値は残る。代わりに装備の耐久を 10% 失う（壊れる手前で止め、壊さない）。または所持の金（エメラルド）の一部。
- **背中**: 預かり（今のまま）。
- **取り戻し**: なし（稼ぎ直し）。共鳴の炉で修理する。
- **緊張**: 弱い。耐久の減りが積もるのが小さな圧になる。
- **マルチ**: 個人ごと。仲間が蘇生すれば代償なしにする案も付けられる。
- **実装**: S〜M。死亡イベントで耐久を減らすだけ。背中の死亡処理（`TitanBackTrials`）と同じ位置に差し込める。
- **注意**: 地上の持ち物の扱いを変えるので、01 の「バニラを置き換えない」の例外になる（背中と同じ扱い。追認が要る）。

### 案 C: 装備は残し、残りは消えない墓（段階案。おすすめ）

- **地上**: 持ち物が二つに分かれる。
  1. 装備中の防具・手に持つ武器・ホットバーは**そのまま持って復活**する（Core Keeper 型）。大事な品も残る。
  2. 残りの持ち物（素材・食料・予備）と経験値の玉は墓に入る（案 A の墓。消えない、持ち主限定、座標は控え帳）。
- **復活地点**: バニラのベッド。なければ最後に触れた鐘（鐘は再開点）。
- **背中**: 今のまま預かり。
- **取り戻し**: 墓を開く。取りに行けないときは、鐘のそばの語り部に頼むと墓の中身の一部（既定 50%）を渡して墓を閉じる救済を置く（代償つきの逃げ道。取りに行く動機も残る）。
- **代償**: 取りに行く手間。ただし戦う手段は手元にあるので、墓までの道中が詰まない。
- **緊張**: 「素材と食料と予備が墓にある」程度。戦えなくなるほどの罰ではない。
- **マルチ**: 墓は個人。パーティ内では仲間が開けて渡せる（設定）。
- **実装**: M。案 A に「装備とホットバーは残す」の振り分けと語り部の救済を足す。`Keepsakes`・`DropLedger`・`PlayerPersisted` の預かり（`skyabyss_kept`）を再利用。

### 案 D: 魂の残り火（Hollow Knight 型を軽くしたもの）

- **地上**: 持ち物は全部残る。代わりに RPG の経験値の一部（現在のレベル内の 10% 程度。レベルは下がらない）が**残り火**として死んだ場所に残る。
- **背中**: 預かり（今のまま）。休み場で復活後に弱体（15%）を 3 分だけ（FFXIV の衰弱型）。
- **取り戻し**: 残り火に触れると戻る。二度死んでも前の残り火は消えない。遠いときは鐘で諦めて失う選択もできる。
- **緊張**: 「戻らないと損」の感覚を、物ではなく成長で作る。物が残るので離脱しにくい。
- **マルチ**: 個人。仲間は触れない。
- **実装**: M〜L。経験値の預かりと残り火のエンティティが新規。死亡時の経験値の処理は新設。
- **注意**: 物を失わないので「死んでも痛くない」状態になりやすい。マイクラの危険な探索の緊張が薄まる。

### 案 E: 世界ごとに選ぶ（Terraria 型）

- **地上**: ゲームルールで型を選ぶ。
  - 物語向け（既定）: 案 C。
  - 自由・サバイバル向け: バニラの全ロス。
  - 気楽: 全部残す（`keepInventory` true）。
  - 上級者向け: 墓を持ち主以外も開けられ、30 分で消える。
- **背中**: 全型共通で今のまま。
- **マルチ**: **サーバー一括**。プレイヤーごとの選択は同じ世界で別の決まりの人が混ざるので避ける（10 の「モードは分けない」と同じ考え）。
- **実装**: S（ゲームルールの束ね）。ただし選べる型が増えるほどテストの量は増える。

### 案 F: 背中の方式を地上にも広げる（現行の延長）

- **地上**: 背中と同じく、持ち物と経験値は預かり、鐘（または最後のベッド）で復活して返る。全ロスをなくす。
- **取り戻し**: 復活したとき自動で戻る（取りに行かない）。
- **代償**: なし、または案 B の耐久 5〜10%。
- **緊張**: 最も弱い。ホラーは「見える怖さ」だけで作る。
- **マルチ**: 個人。
- **実装**: S。`skyabyss_kept` の仕組みを地上の死にも使うだけ。
- **注意**: マイクラの基本の緊張（洞窟に潜る怖さ）をなくす。「マイクラらしさは壊さない」（01 の 3）に触れる。

## 3. おすすめ

**案 C を既定にして、案 E の形（ゲームルールで切り替え）で出す。**

理由:

1. 感想の二つの不満（全ロスの萎え／取りに行く面倒）の両方に答える。装備とホットバーが残るので、死んだ直後でも戦える。取りに行くのは素材と予備だけなので、面倒でも詰まらない。
2. 比較表で受け入れられている型は「物は残して小さな代償」（DQ・Diablo・Core Keeper）と「消えない墓」（Valheim・GraveStone）。C はその合わせ技。
3. 「時間で消える墓」と「二度目の死で消える回収物」は憎まれやすいので入れない。
4. マイクラの緊張は残る（洞窟で死ぬと素材が墓に残る）。背中は今のまま預かりで、ホラーの「殺さない」とも矛盾しない。
5. 実装は既存の `Keepsakes`・`DropLedger`・控え帳 B・預かりの仕組みで組める。新規は墓ブロックとその保存、語り部の救済の会話だけ。
6. 序盤の方針（17）とも合う。墓の導入を序盤の拍子の一つにできる。

### ゲームルールの案（仮の名前）

### 決めること

1. 地上の既定を案 C にしてよいか。
2. 大事な品は死んでも手元に残す（00 の 88 の「三つとも残す」）でよいか。
3. 地上でも経験値の玉を落とさず墓に入れる（01 の「バニラを置き換えない」の例外。背中の T5 追認と同じ判断）でよいか。
4. 語り部の救済（50%）を入れるか。入れないと、取りに行く手間が残る。

実装は決まってから別の作業にする（このページは調査だけ）。
